## 1. 目标与范围

先把已有能力做成可见、可验证的闭环，再接入 Agent 路径，最后补真实环境证据。沿用 A00–A13 编号，以小数后缀表示可独立验证和提交的收尾包。A00–A13 共 14 个原始工作包。

本批优先完成 A02.1、A01.1、A04.1、A09.1、A02.2、A06.1；每包验证通过后创建独立本地提交。A00 继续暂缓；A10、A11、A12 质量评测不进入本批。本文只提交计划，不自动执行后续功能、外部推理、部署或发布。

## 4. 工作包验收

### A-E0：证据口径与验证环境核对

- 核对历史提交、测试收集数量及可用原始报告，记录命令、源码版本、运行环境、通过/跳过/排除项；无法找到来源时标记“历史陈述，未复核”。
- 核实 Node、浏览器验证能力、uv、独立框架 Python 3.12 和模型端点的可用性。当前 shell 找不到 node 不等于整机没有 Node；历史环境阻塞不能直接沿用。
- 同步原计划和实施记录的能力边界、统计口径及本计划入口；保留历史结果和更正依据。A00 的简历及 LawBench 数字同步继续暂缓。
- 验收：不再出现无依据的“全部完成”“全量通过”；工程、模型、业务验收分别列示。
- 建议提交：`docs(migration): 核对升级证据与未完成验收项`。

### A02.1：用量与延迟面板（第一个功能提交）

- 复用 `platform-metrics` 的 llm_usage，展示调用数、失败数、输入/输出 tokens、TTFT P50/P95、调用延迟 P50/P95，以及模型/调用类型分组。
- 空样本、缺失 usage、部分调用有 usage 时分别显示；部分已知 token 合计明确为“已知部分”，附可用样本数或覆盖率。0 与未知不能混淆。
- 区分模型调用 TTFT、调用延迟、整次问答延迟和浏览器首字可见时间，不混用名称或分母。
- 验收：正常、空案件、部分缺失、请求失败、快速切换案件不串数据显示；实际运行页面完成展示验证。此包不展示虚构金额。
- 主要路径：`app/static/index.html`、`app/static/app.js`、`app/static/styles.css`、`app/llm_usage.py`、`tests/test_llm_usage.py`；API 与页面测试随实际改动补充。
- 建议提交：`feat(metrics): 展示模型用量与延迟及缺失数据状态`。

### A01.1：流式协议、断连与重复提交

- 固定成功事件顺序与失败终态：首 token 前有 status；token 为待校验草稿；结构化 citations 在校验成功后发送；done 携带实际可用的问答标识、TTFT、usage。聊天不创建 agent_runs，不伪造 run_id。
- 明确现有 final 的兼容策略并同步桌面客户端；失败 retract 后清除草稿，结束事件不伪装成功。区分“引用对象延后挂载”与模型正文可能输出的引用标记。
- 增加协作取消与请求幂等语义。断连发生在提交前应停止后续业务写入；提交后断连重试返回已有结果。使用明确事务提交边界，避免取消与提交竞争造成重复消息或半条成功记录。
- 已发生的模型调用保留真实用量/失败/取消状态，不因断连删除账本；取消不能立即打断底层读取时，仍受既有绝对超时约束。
- 验收：首 token 前断连、生成中断连、校验失败、提交边界竞争、相同请求重试、正常结束；验证事件顺序与数据库最终状态。原非流式接口回归通过。
- 主要路径：`app/main.py`、`app/services.py`、`app/static/app.js`、`tests/test_chat_stream.py`；必要的数据库迁移使用届时最新版本号，不硬编码 v18/v19。
- 建议提交：`fix(chat): 完善流式终态与断连重试一致性`。

### A04.1：Agent 工具循环接入

- 在 `app/agents.py` 的适用检索路径复用 `app/tool_loop.py` 与现有工具执行器；不复制第二套参数校验和出口实现。
- 服务端注入案件范围和调用身份；保持只读白名单、参数界限、3 轮/6 次等现有上限、预算治理与 data_notice。不支持 tools 时显式回退并记录原因。
- 工具结果、卷宗正文、历史消息、文件名均作为不可信数据；分别测试攻击被拒和正常输入可用，覆盖跨案件访问及禁止写操作。
- 验收：正常闭环、非法工具、越界参数、无 tools、达到上限、工具错误、治理拒绝；答案仍通过既有引用校验，轨迹记录调用与结果状态。
- 区分 native DAG、LangGraph 等实际受影响运行路径；未接入的路径明确标注。不得借此切换 ForgeHarness 正式业务入口或跳过已有接入门槛。
- 建议提交：`feat(agents): 接入受治理的只读工具循环`。

### A09.1：Agent 一次性模型回退

- 复用 `app/model_router.py`；明确触发条件和 route_reason，仅在符合既有回退策略时最多重试一次，不新增无依据的“低置信”阈值。
- 主模型与回退模型使用同一案件范围及答案校验；禁止用回退绕开权限拒绝、出口拒绝或治理预算。
- 每次调用关联同一逻辑问答/运行与相应节点，分别记录模型、用量、延迟、状态；取消或恢复不能无意重复调用。
- 验收：主模型成功不回退、主模型拒答/失败按契约处理、回退成功、二次校验失败、半配置、远端被禁；按注入测试覆盖两条路径。
- 建议提交：`feat(agents): 接入一次性模型回退并记录原因`。

### A02.2：可复算的问答级估算费用

- 配置模型输入/输出 token 单价、币种、单位、来源与生效版本，调用记录绑定定价快照，避免改价重算历史。数值精度与舍入规则固定并测试。
- 单次问答费用包含该逻辑问答的工具循环、主模型、回退模型等已发生调用；按调用金额与按问答金额分别报告，防止把二者混为一谈。
- usage 或价格缺失时，总费用保持未知；可展示明确标注的“已知部分费用”及覆盖率。没有 usage 的失败调用不能计为免费。
- 本地模型无已定义的资源成本模型时显示“未配置成本”，不写 ¥0。按 token 单价计算的金额标注“估算费用”，不称为实际账单。
- 验收：手算样例一致，覆盖正常、多轮、回退、失败、部分缺失、历史改价、重复请求；页面可比较路径，但无真实测量时不宣称节省比例。
- 建议提交：`feat(metrics): 增加可追溯的问答级费用估算`。

### A06.1：页面与完整链路验收

- 轨迹展示节点耗时、调用模型、已知 tokens、工具结果状态、回退原因与失败节点；未知值保持未知，禁止展示隐藏思维链或未经筛选的敏感提示内容。
- 在加载当前代码的隔离服务中验证三条页面流程：正常流式回答与引用回原文；校验失败/断连撤回与重试；Agent 工具/回退轨迹及指标面板。
- 用可控模型响应做页面流程验证时明确标注测试替身；真实模型验收由 A05.1 单列。新增浏览器依赖须锁定并纳入适用 CI。
- 验收：三条实际页面流程和适用完整离线检查通过；失败可定位，刷新及案件切换不遗留上个案件内容。
- 建议提交：`test(ui): 验证流式问答指标与 Agent 轨迹流程`；若需独立 UI 功能改动，先拆出对应功能提交。

### A05.1：真实客户端与模型验证

- 用可用的 Cursor 或 Claude Desktop 对隔离演示案件执行 initialize、list_tools、正常调用、未知工具和跨案拒绝；记录客户端版本与协商结果。维持 token 模式拒启动边界。
- 使用明确获准的模型端点实跑原生 tools 和双模型回退；记录模型/服务配置、提示版本、实际调用、usage 缺失、延迟与最终校验结果。
- 验收：协议替身测试与真实客户端、脚本化模型与真实模型四类结果分开列示；缺端点或客户端时保留未验证状态，不以单元测试代替。
- 工程修复与脱敏验证报告分别按主题提交；未经授权不使用付费/外部服务，不上传真实案件资料。

### A07.1 / A08.1：答案级质量闭环

- A07.1：在 `benchmarks/answer_eval/` 冻结 50–100 题，涵盖正常、矛盾、证据不足、无关问题、法条缺失与注入；每题有来源、必需要点、可接受引用及数据版本。校验器检验唯一 ID、页码和来源一致性；与页级检索评测分开报告。
- A08.1：固定 judge 模型、提示版本及评分规则；人工抽检至少 20 题，冻结抽样名单后评分。预先定义 κ 的离散标签映射，报告逐题结果、分歧、样本数及无法计算的退化情形。
- judge 不可用、输出无法解析或人工标签缺失时，该项明确失败/未完成；只有实际完成语义判定且满足约定条件时才允许 semantic_entailment_checked 为 True。
- 验收：结果可复算，自动标注与人工标注如实区分，负结果不删除；无人工标注不得宣称“人工一致性已验证”。数据集与 judge 报告分开提交。

## 6. 验证门禁与提交规则

- 纯文档：核对引用、命令、算术与 diff，不运行无关业务测试。Python 改动运行受影响测试及 `uv run --locked ruff check app tests scripts`；工程脚本或类型配置改动增加 `uv run --locked mypy`。
- 前端改动运行 `for script in app/static/*.js; do node --check "$script"; done`，并实际验证受影响页面。缺运行时应解决环境或如实阻塞，不把代码审查记为页面验证。
- 跨模块、迁移、依赖或准备合并时执行 `.github/workflows/test.yml` 对应完整检查：依赖导出一致性、doctor、compileall、Ruff、Mypy、Node、禁网测试及覆盖率、发布允许清单。当前离线矩阵为 Python 3.11/3.14；框架进程另用独立 Python 3.12。
- 依照 CI 配置使用隔离数据目录与 checkpoint 数据库，禁用自动 pytest 插件加载，显式加载 pytest_cov/pytest_socket，禁用网络 socket 并仅允许所需 Unix socket；不任意排除失败测试。覆盖率门槛保持 70%。
- 通过 `uv run --locked python -m scripts.setup_framework --output <新的环境目录>` 准备独立框架环境，并设置 LAW_REVIEW_FORGE_PYTHON 后实跑。缺变量导致的 M2 跳过不算集成通过，详见 [质量运行手册](../runbook/quality.md)。
- 新依赖同步锁文件及 requirements 导出，并按 `.github/workflows/security.yml` 执行适用依赖审计；保留 `egress_opener`、`assert_model_endpoint_allowed`、`governed_backend` 及 allow_remote_models 限制。
- 每包只暂存明确路径，审查工作区 diff、暂存 stat/diff，并运行 `git diff --cached --check`。必要检查无法完成时不创建冒充完成的提交；不推送、不合并、不改写历史。
- 交付记录包含提交哈希、源码与环境身份、检查命令、通过/失败/跳过/未执行项、证据位置和工作区状态。真实案件、密钥、数据库、模型权重、原始响应及临时日志不进入 Git。

## 7. 第一批放行标准

1. 用量面板可见且不把未知数据当作零；费用可从价格快照与实际调用归属复算。
