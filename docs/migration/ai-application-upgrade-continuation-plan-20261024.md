### A01.1：流式协议、断连与重复提交

- 固定成功事件顺序与失败终态：首 token 前有 status；token 为待校验草稿；结构化 citations 在校验成功后发送；done 携带实际可用的问答标识、TTFT、usage。聊天不创建 agent_runs，不伪造 run_id。
- 明确现有 final 的兼容策略并同步桌面客户端；失败 retract 后清除草稿，结束事件不伪装成功。区分“引用对象延后挂载”与模型正文可能输出的引用标记。
- 增加协作取消与请求幂等语义。断连发生在提交前应停止后续业务写入；提交后断连重试返回已有结果。使用明确事务提交边界，避免取消与提交竞争造成重复消息或半条成功记录。
- 已发生的模型调用保留真实用量/失败/取消状态，不因断连删除账本；取消不能立即打断底层读取时，仍受既有绝对超时约束。
- 验收：首 token 前断连、生成中断连、校验失败、提交边界竞争、相同请求重试、正常结束；验证事件顺序与数据库最终状态。原非流式接口回归通过。
- 主要路径：`app/main.py`、`app/services.py`、`app/static/app.js`、`tests/test_chat_stream.py`；必要的数据库迁移使用届时最新版本号，不硬编码 v18/v19。

### A11：前端重写与 FastAPI 分工

目标技术栈为 **Next.js + React + TypeScript 前端，FastAPI + Pydantic/Python 业务后端**。FastAPI 已在项目中使用，本次继续承担案件与文档 API、鉴权、SSE、检索、模型调用、工具循环、引用校验及数据库访问。Next.js 负责页面路由、交互、状态和展示；模型密钥及数据库访问保留在 Python 服务端。

```text
浏览器：Next.js / React / TypeScript
    ↓ 同源 /api 请求、文件请求与 SSE
本地统一入口：页面 → Next.js；API/受保护文件 → FastAPI
    ↓ FastAPI 鉴权、校验、审计与出口治理
既有 Python 检索 / Agent / 模型适配器 / 数据存储
```

默认采用 Next.js 服务与 FastAPI 服务配合同源反向代理，记录新增 Node 运行时、启动、健康检查和发布依赖。代理必须透传 SSE、禁止缓冲流式答案、传递取消，并保持认证与客户端身份边界；不得因为所有请求来自本地代理就把远端访问当作可信本机访问。开发若使用不同源，明确允许的来源与凭据规则，参见 [FastAPI CORS 文档](https://fastapi.tiangolo.com/tutorial/cors/)。

Next.js 可提供 [Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)，本项目的业务 API 仍统一由 FastAPI 实现。若确需增加前端服务层代理，必须验证身份透传、取消、超时和流式行为，不复制业务规则。运行时与框架版本在实施时核实兼容性并锁定，不使用浮动版本作为验收环境。

- 开发阶段允许临时并存用于对照；功能清单和新页面验收通过后切换单一正式入口，移除旧前端的正式路由与构建依赖，避免长期双前端维护。保留旧版本发布包和入口配置作为回滚方案，不做破坏性 Git 恢复。
- 旧 UI 测试按同等业务断言迁移；不因重写删除失败场景或降低门槛。更新发布允许清单、Docker/本地启动文档及 `AGENTS.md` 中的前端验证命令。
- 验收：前端构建/类型/lint/依赖审计、E2E、后端适用完整检查及发布复现通过，旧入口替换和回滚演练有记录。测试替身通过与真实模型效果仍分开报告。
- 建议将验证与部署切换拆成独立提交：`test(frontend): 覆盖新前端主流程与异常路径`、`build(frontend): 切换新前端入口并更新发布流程`。

### A05.1：真实客户端与模型验证

- 用可用的 Cursor 或 Claude Desktop 对隔离演示案件执行 initialize、list_tools、正常调用、未知工具和跨案拒绝；记录客户端版本与协商结果。维持 token 模式拒启动边界。
- 使用明确获准的模型端点实跑原生 tools 和双模型回退；记录模型/服务配置、提示版本、实际调用、usage 缺失、延迟与最终校验结果。
- 验收：协议替身测试与真实客户端、脚本化模型与真实模型四类结果分开列示；缺端点或客户端时保留未验证状态，不以单元测试代替。
- 工程修复与脱敏验证报告分别按主题提交；未经授权不使用付费/外部服务，不上传真实案件资料。

### A07.1 / A08.1：答案级质量闭环

- A07.1：在 `benchmarks/answer_eval/` 冻结 50–100 题，涵盖正常、矛盾、证据不足、无关问题、法条缺失与注入；每题有来源、必需要点、可接受引用及数据版本。校验器检验唯一 ID、页码和来源一致性；与页级检索评测分开报告。
- A08.1：固定 judge 模型、提示版本及评分规则；人工抽检至少 20 题，冻结抽样名单后评分。预先定义 κ 的离散标签映射，报告逐题结果、分歧、样本数及无法计算的退化情形。
- judge 不可用、输出无法解析或人工标签缺失时，该项明确失败/未完成；只有实际完成语义判定且满足约定条件时才允许 semantic_entailment_checked 为 True。
- 验收：结果可复算，自动标注与人工标注如实区分，负结果不删除；无人工标注不得宣称“人工一致性已验证”。数据集与 judge 报告分开提交。

### A13.1：演示与交付

- 基于 A11.4 验收后的新前端、通过验证的源码及合成案件制作 3 分钟演示：建案、导入、提问、引用回原文、证据不足/法条拒答，再展示用量与轨迹。
- 核对 README、英文说明、安装命令及许可证状态；许可证选择需确认项目及第三方权利，不能把计划当作开源授权。
- 验收：从隔离环境复现演示，记录源码版本、模型配置和限制。规则模式演示须明确标注，不能称为真实模型效果。
- 在线体验、公开仓库发布与外部社区发帖分开办理；无部署与发布授权时只准备可审阅材料。

## 6. 验证门禁与提交规则

- 纯文档：核对引用、命令、算术与 diff，不运行无关业务测试。Python 改动运行受影响测试及 `uv run --locked ruff check app tests scripts`；工程脚本或类型配置改动增加 `uv run --locked mypy`。
- 前端改动运行 `for script in app/static/*.js; do node --check "$script"; done`，并实际验证受影响页面。缺运行时应解决环境或如实阻塞，不把代码审查记为页面验证。
- A11 新前端建立独立的锁文件安装、TypeScript 类型检查、lint、生产构建、依赖审计及 Playwright 门禁；旧脚本仍存在期间继续执行原语法检查。待 A11.4 完成等价覆盖迁移后同步仓库规则，不把旧语法检查当作 Next.js 构建验证。
- 跨模块、迁移、依赖或准备合并时执行 `.github/workflows/test.yml` 对应完整检查：依赖导出一致性、doctor、compileall、Ruff、Mypy、Node、禁网测试及覆盖率、发布允许清单。当前离线矩阵为 Python 3.11/3.14；框架进程另用独立 Python 3.12。
- 依照 CI 配置使用隔离数据目录与 checkpoint 数据库，禁用自动 pytest 插件加载，显式加载 pytest_cov/pytest_socket，禁用网络 socket 并仅允许所需 Unix socket；不任意排除失败测试。覆盖率门槛保持 70%。
- 通过 `uv run --locked python -m scripts.setup_framework --output <新的环境目录>` 准备独立框架环境，并设置 LAW_REVIEW_FORGE_PYTHON 后实跑。缺变量导致的 M2 跳过不算集成通过，详见 [质量运行手册](../runbook/quality.md)。
- 新依赖同步锁文件及 requirements 导出，并按 `.github/workflows/security.yml` 执行适用依赖审计；保留 `egress_opener`、`assert_model_endpoint_allowed`、`governed_backend` 及 allow_remote_models 限制。
- 每包只暂存明确路径，审查工作区 diff、暂存 stat/diff，并运行 `git diff --cached --check`。必要检查无法完成时不创建冒充完成的提交；不推送、不合并、不改写历史。
- 交付记录包含提交哈希、源码与环境身份、检查命令、通过/失败/跳过/未执行项、证据位置和工作区状态。真实案件、密钥、数据库、模型权重、原始响应及临时日志不进入 Git。

## 7. 第一批放行标准

1. 用量面板可见且不把未知数据当作零；费用可从价格快照与实际调用归属复算。
2. 流式成功/失败终态明确，断连与重试不产生半条成功记录或重复问答。
3. Agent 工具与回退接入后，权限、出口治理、引用校验和注入测试保持有效。
4. 三条实际页面流程及适用完整离线检查通过；真实模型、人工评分与线上部署仍按各自证据判定，不从工程通过外推。
5. A11 阶段放行还须完成既有功能清单迁移、新前端 E2E、同源代理/认证/SSE 验证、发布包复现和回滚演练，再切换正式入口。
