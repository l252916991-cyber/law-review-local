## 4. 领域接入的关键设计要求

### 4.1 固定业务图及可重建上下文

以当前 `PlannerAgent` 的路由和节点依赖为准，覆盖 planner、memory_recall、retrieve、facts、evidence、按题触发的 contradiction / statutory_conflict / gap_detection、critic、引用验证和完成投影；`persist_memory=false` 时不产生记忆写入。保留既有依赖约束，gap_detection 等待其声明的前驱，critic 等待所需专家输出。

D01 须说明如何在首次执行时冻结动态规划结果及完整图身份。恢复使用原计划，禁止重新规划后把新节点接到旧审批或 checkpoint 上。工具调用/副作用按稳定的 run、node、逻辑动作和内容身份关联，不以重试次数生成新动作。

`ReadonlyCaseSession.outputs` 和临时快照不能直接作为持久事实。须设计受授权的快照保留、结果物化或按已保存身份重建方案，覆盖检索包、记忆输入、专家输出、法条语料身份及模型配置。框架复用已完成节点时，宿主后续回调仍须取得经校验的前驱输出；不能为重建内存再次调用模型或重写消息。恢复时当前权限、输入版本不符则拒绝或进入明确处理状态，不静默换新材料。

执行状态由框架持久图负责；宿主保存映射、受信业务回执和可重建投影，不另建节点调度器。继续使用单 Web、≤2 后台任务、准入 4 的工程范围；图分支/join 支持不等于外部调用并发已经通过验收。

### 4.2 把领域输出纳入可信写契约

当前隔离控制只派发预先保存的动作，写端口的 `conversation_message` 仅允许空引用，步骤仅写合成完成记录，worker 使用 `NoopVerifier`。D02/D03 必须逐项设计领域替代方案，不能只删除这些校验或把运行时名称换掉。

- 保持六类 `WriteAction` 的公共边界，明确节点开始/完成/失败、最终答案/引用及审计分别由哪个动作或受信投影更新；字段或语义改变时记录版本兼容方案。
- 动态输出由受信宿主按节点、保存输入及输出 schema 验证和绑定；sidecar 提交任意 payload 不构成写入授权。最终引用须核对案件/文档/页码/引文或法条语料身份，跨案、伪造、过期引用拒绝。
- 案件输入、外部法条和模型身份分别固定；运行自身生成的步骤、草稿、消息不能使输入版本自我失效。查询旧回执也重新授权，来源变化或效果已被修改时不返回失效成功。
- 同一事务保存业务效果和回执，取消/原绝对 deadline 检查纳入写入边界。恢复重用已提交效果；无回执但已派发的调用保持 unknown，除非有可信未执行证明。
- `memory_draft` 保持待核验，不能进入已验证事实召回；缺口保持待核验。框架执行审批与证据业务审批分别处理，普通内部保存不额外增加统一人工审批。
- 完成前执行真实引用校验；无来源、非法引用、模型失败分别记录，不能因为 join 完成就显示法律审查成功。保留合成第 4 题的无来源拒绝作为回归场景。

### 4.3 后端治理与未知结果

实际模型路径只使用宿主受信配置，冻结生成/embedding/reranker 的权重身份、revision、有效参数、端点类别和输入摘要。模型名相同不能代替同权重证明；请求正文不能覆盖凭据、服务地址或准入规则。

模型调用次数、token、费用、预留与绝对 deadline 的持久事实必须跨重启延续。调用已发送但结果/用量未知时，保持待对账；不得按合成工具的“一次调用”推定真实 token 或费用，不能自动重发导致重复费用。将模型调用与业务写入分别设故障边界。

离线替身验证协议和失败语义；实际本机服务即使无 API 费用，也要核验模型身份与运行条件。无法取得实际用量时标记未知，降级和失败单列，治理开销单列。正式入口的旁路按 E01 留账，到 E14 再逐项关闭并提供调用治理证据。
