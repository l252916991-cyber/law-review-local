## 4. 真实 Tesseract OCR 与人工纠错

已安装 Tesseract 5.5.4、Poppler 26.10.0，使用 `/opt/homebrew/bin` 程序与 `chi_sim+eng`。VLM OCR 关闭。两页 PDF 经检查仅含图像、没有可提取文字；另有清晰 PNG 和 1.1° 倾斜、0.5 px 模糊的 PNG。姓名、编号、金额和日期均为虚构，样本及真值在首次 OCR 前固定。

判定对真值和输出均做 Unicode NFKC 及空白归一化，其余字符不擅自纠正；CER 为编辑距离/真值字符数。金额、日期、编号按数字及小数边界精确匹配。

| 样本 | CER | 预设上限 | 关键字段 |
|---|---:|---:|---:|
| 纯扫描 PDF 第 1 页 | 1.39% | 2% | 4/4 |
| 纯扫描 PDF 第 2 页 | 0% | 2% | 4/4 |
| 清晰 PNG | 0% | 2% | 4/4 |
| 轻度退化 PNG | 3.52% | 8% | 4/4 |

真实 HTTP 上传/提取总计 2.705 秒，16 个关键字段全部正确，达到上述技术门槛。**姓名仍发生误识别**：PDF 第 1 页的合成姓名识成 `AT`；退化图片中的两个姓名识成 `BRE`、`AT`。原始 OCR 与差异均保存，没有调整原文、真值或门槛来换取通过。

随后单独通过真实 API 验证人工纠错：创建引用该误识字符串的已确认证据，人工按固定真值纠正姓名后，材料版本 1→2，证据版本 1→2，证据自动退回待复核，确认人/时间清除，原文纠错及审批失效审计存在。9 项检查通过。OCR 原始结果、协议及所有真值/提取文本的摘要前后相同；**人工纠错后的文本没有重新计入 OCR 指标**。

证据：`ocr/protocol.json`、`result.json`、`correction-check.json`、原始 OCR 文本及样本。此结果只覆盖机器生成的清晰及轻度退化打印文字，不覆盖客户低质卷宗、手写、印章、复杂表格或律师业务复核。

## 5. 本机真实模型：固定技术协议通过，法律表述仍需复核

固定协议 `models/protocol.json` 包含 12 道合成事实/矛盾/缺失信息问题，要求受控事实和引用字段核对全部通过、非预期失败率 0、至少 10 次真实模型答复、真实模型答复 p95 ≤90 秒；3 个可编辑身份请求模型，另 2 身份并发读取。warmup 不进入题目或延迟评分。

该合成协议已原样保存为 [`scripts/fixtures/local-model-acceptance-v1.json`](../../scripts/fixtures/local-model-acceptance-v1.json)，与运行输入逐字节一致，12 份保存的真实模型响应重新按该协议核对通过。它随源码交付包分发，不含真实案件材料。

预热记录单独保留：12.026 秒的首次预热只有 reasoning 截断，不算正文答复；与产品一致禁用 thinking 后，0.854 秒返回预期正文，仍排除在题目和评分之外。验收结束关闭本任务启动的临时模型服务，释放其内存；ComfyUI 服务继续保留。

## 6. 可观测故障与恢复演练

在另外新建的隔离合成实例执行 `ops-drill/run1/`，模型和 Redis 均指向不可达回环端口；没有改动验收主实例、用户模型服务或系统磁盘。实际结果：

- 模型不可达时，真实 `/chat` 返回 503 和 `model_unavailable_or_invalid`，提示检查模型/内存并重试；没有保存助理回答，请求记录为失败，数据库完整性正常。本轮补齐了此前只返回 500 的错误分类，未放宽输出校验。
- 既有验收工具带 `--probe-model` 实际退出 1。仅在演练探测进程将可用空间门槛设为实测空闲量加 1 字节，容量检查退出 1 并指向 `free_space`；没有填满磁盘或调整产品阈值。
- 无效备份目标触发真实备份失败，验收退出 1 并指向 `backup_drill`；换成新的合法目录后备份、验证、恢复退出 0，源库字节摘要不变。
- Redis 不可达时，系统健康接口明确报告 `redis=unavailable`、`batch_import=disabled`，真实批量上传被 503 拒绝。一次性队列判定命令退出 1。**现有验收 CLI 没有队列检查项，基础巡检仍可能退出 0**，不能用其单独证明 worker 可用。

这些证据验证可观测失败及恢复，不等于告警已交给真人值班。没有安装定时任务或发送外部通知；消费者心跳、真人收到告警并处理、真实满盘及长期备份留存均未验。工具存在队列巡检覆盖缺口，应在正式使用批量导入前补入值守方案。结果文件 SHA-256：`e358a158ccaf43ce920b2ca80d2e91af76604fb7ad9604b50719d482cd3c3ed3`。
