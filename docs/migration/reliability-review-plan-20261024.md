## 2. 人员与两条执行路径

角色是待落实的责任分工，执行记录须填写实际承担者，不能以角色名称代替评审签认。

| 角色 | 责任与交付 |
| --- | --- |
| 项目负责人 | 落实试用者、排期与材料范围，接收结论并决定后续投入；对外邀请由负责人发送，或另行明确授权代发 |
| 实现维护者 | 冻结版本与样本、准备可核验材料包、记录问题、实施修复和回归验证 |
| 独立事实复核者 | 未参与本轮回答生成、提示调优与评分规则设计；先读原文列事实清单，再看回答逐项核对 |
| 法律背景试用者 | 说明背景及相关经验，完成提问、核验和反馈；可以兼任独立事实复核者，但须披露兼任情况 |

**路径 A：有法律背景使用者参与。** 优先安排至少 1 人、一次 60～90 分钟试用及一次约 30 分钟结果复核。首轮是发现问题的小样本试用，不称为代表性用户研究。法律学习或相关工作背景可支持试用反馈；专业法律结论须记录相应资格与经验，不能将一般试用者意见自动视为 E17 专业终评。

**路径 B：暂时没有这类使用者。** 先由未参与实现的复核者完成同一套事实核验。若只有自动化复核工具可用，使用不读取生成推理或既有自评分数的独立核验过程，逐项附原文证据，标为“自动化事实核验、待人工确认”。如果只能由原开发者检查，则标为“开发者原文自审”，不称为独立评审。以上替代路径均不评价专业法律适用正确性，也不代替使用者可用性反馈。

第 2 个工作日结束仍未落实法律背景试用者时，启动路径 B，同时保留路径 A 为待办；不以等待评审人为由停下材料和证据准备。

## 3. 样本与冻结规则

1. **已见材料作为回归集。** 沿用上批 24 道不同题（18 道回归题＋6 道原保留题），四个已知问题单列；重复运行单独统计，不增加题目或案件数。
2. **新增保留集至少 2 个未用公开案例、6 道题。** 候选修复冻结后，由复核者按以下覆盖要求选题：金额/日期/地点等明确事实、主体与处理结果、类别或认定结论、跨段核对、材料不足或超出范围。首次运行前冻结题面、必答事实、允许的等义表达、拒绝预期和评分标准。
3. **人工试用至少覆盖 8 道不同题。** 包含四个已知问题和至少四道新保留题；先完成不带提示的试用，再向试用者展示已知缺陷。所有新保留题仍须完成逐项事实核验；试用者自由追问另列为探索题，不混入冻结通过率。
4. 每份材料登记发布机构、标题、原始链接、获取日期、材料类型（摘要/全文）、本地快照哈希及页码或段落编号。优先使用官方公开材料；没有完整裁判文书时，明确“本文原文”为公开摘要，不能补推摘要未载事实。
5. 先从原文建立独立参考清单，再展示模型回答。各条参考事实须有准确位置和必要短引文；不能直接拿模型答案生成标准答案。材料存在歧义时登记“待裁定”，不得猜填。
6. 冻结源码提交、实际模型与配置、提示/语法、检索库与材料身份、运行顺序及重复安排。保留集一旦用于调整实现或提示即转为开发材料，下轮另设新保留集。

本轮规模是小样本发现与验证设计，不降低 E17 的“至少 16 个独立业务题”等既有要求，也不冒充该终评集。

## 4. 核验方法与试用流程

### 4.1 先核对事实，再形成质量判断

把每个回答拆成可核验的最小陈述，分别判断：

- **支持性：** 原文直接支持、仅部分支持、原文矛盾、原文未载或存在歧义。引用格式正确或关键词命中不能自动判为支持。
- **完整性：** 问题要求的金额、时间、地点、公司类别、认定结论等必答项是否写在回答正文；引文中出现但正文遗漏仍记遗漏。
- **主体与语境：** 区分当事人主张、查明事实与裁判/仲裁结果；区分不同阶段和适用条件。
- **可定位性：** 引用是否指向正确材料和原页/原段；该段是否确实支撑对应陈述，而不只是讨论同一主题。
- **边界表达：** 材料不足时是否明确限定为“本次材料未见”，是否避免将资料中的个案结论写成普遍法律规则。

差异记录同时保留模型输出、参考事实和判断理由。评分口径有争议时先登记，不为提升通过率修改标准；确需纠正规则，发布新清单版本、说明受影响范围并重新评测。

### 4.2 法律背景使用者的实际任务

1. 使用者阅读简短任务说明，自行提问或执行冻结题；观察者只处理操作故障，不提示答案及引用位置。
2. 使用者指出回答中的关键结论，并通过现有引用入口找到原文，说明该段是否足以支持结论；记录成功与否、耗时、点击/查找步骤、是否需要帮助。
3. 使用者指出遗漏、错误或不确定内容，填写“可用于资料定位 / 需修改后再用 / 不可依赖”的判断及具体原因。
4. 结束后访谈：最难核验的三处是什么、哪些遗漏会影响工作、哪些展示或引用问题最值得先修。

试用必须登记实际入口、启动版本和数据范围。候选尚未接正式入口时，可用隔离运行输出与可定位原文材料包完成内容核验，但必须标注“材料包核验”；不能用原生页面结果冒充候选 UI 验证，不能据此声称 E15 通过。若使用实际页面，应确认服务加载冻结代码并保留流程证据。

## 5. 记录格式与验收标准

每题记录至少包含以下字段，可作为人工表单使用；与现有 [G2 评审模板](g2-review-template.json)关联，保留其资格字段含义。

| 记录组 | 必填内容 |
| --- | --- |
| 身份 | 题号、案例编号、材料/题集哈希、候选提交与运行 ID、实际入口 |
| 原文参考 | 问题、必答事实及重要性、页/段位置、必要短引文、资料范围限制 |
| 回答核验 | 原始回答、逐项陈述及对应引用、支持性判断、遗漏项、角色错误、引用定位结果 |
| 使用者反馈 | 任务是否完成、核验耗时、是否求助、原话摘要、具体改进建议；无人试用时填“未执行” |
| 复核与处理 | 复核者代号/背景/独立性、日期、严重性、争议、负责角色、修复提交与复验结果 |

本轮标准在首次执行前冻结；以下为本计划的目标，尚无实测结果：

| 指标 | 统计口径与本轮目标 |
| --- | --- |
| 参考清单覆盖 | 所有冻结题都有原文参考、必答项或拒绝依据；缺失即未完成 |
| 事实与角色正确 | 每条可核验陈述均有结论；未获支持的确定性陈述、与原文矛盾、主体错置为 0；争议未决不得计通过 |
| 关键事实完整 | 每题全部必答项在正文中正确呈现；报告逐题通过数/总题数，不能仅用平均覆盖率放行 |
| 引用可核验 | 全部引用可定位且支持关联陈述；引用身份错误为 0 |
| 使用者核验完成 | 实际试用的每题均记录能否无帮助定位并判断依据；全部完成为本轮目标，未完成项列为阻断该体验目标的问题；耗时报告逐题值和中位数，不预设未经验证的效率承诺 |
| 专业意见 | 实际参与者确认反馈记录，并给出适用范围与未解决问题；无人参与则为未执行 |
| 工程与成本 | 若修改候选，继续执行既有两类对照；有效同链路配对逐题及总量 token 比 ≤1.10、p95 比 ≤1.20，0 系统失败，新批用量全部已知；无效配对单列 |

问题分级：P0 为虚构事实、结论与原文矛盾、主体错置或引用身份错误等会误导判断的问题；P1 为必答细节遗漏、无法定位依据或误拒可回答问题；P2 为不影响事实的措辞与操作效率问题。P0/P1 在本轮范围内未关闭时，不声明本轮可靠性验收通过。修复优先级不能覆盖既有零容忍门槛。

`semantic_entailment_checked` 仅在逐项语义核验确已完成且覆盖范围有记录时填写；自动化核验须明确方法与局限，不由该字段推导专业资格。`g2_accepted`、`e17_qualified`、`production_qualified` 继续按各自完整门槛判定，不能随一次试用或事实核验自动变为 true。

## 6. 实施安排与投入约束

以下为启动后的建议工期，依赖实际评审排期，不是已确认日程。

| 阶段 | 主责 | 工作与产物 | 完成条件 |
| --- | --- | --- | --- |
| 第 1～2 个工作日：准备 | 项目负责人 / 维护者，主责项目负责人 | 落实评审人；整理现有回答与原文；冻结参考清单和记录表；形成四个已知问题的证据卡 | 材料可复查，复核身份与 A/B 路径确定 |
| 第 3 个工作日：首次核验 | 独立复核者；无人时由维护者注明替代方式 | 对现有输出开展原文核验；有试用者则执行第一轮任务并收集反馈 | 逐题结论、问题严重性与证据齐全 |
| 第 4～5 个工作日：修复 | 维护者 | 按核验结果处理三类遗漏与断言错误；修复实际发现的引用/展示障碍；补有实际断言价值的测试 | 小范围改动通过相应工程检查，候选重新冻结 |
| 第 6～7 个工作日：复验与评审 | 事实复核者 / 法律背景试用者，主责事实复核者 | 回归集＋新保留集实测；完成至少 8 题试用（路径 A）；对照修复前后记录并提交结论 | 本轮目标逐项给出通过/失败/未执行及证据 |

首轮完成证据核验前，暂停新增分析节点、扩充编排和模型升级。后续仅为已证实的问题投入实现工作；优先处理错误与遗漏、引用定位和必要的边界提示。若现有方案连续两轮仍无法满足冻结必答项，先评估检索、上下文和输出限制的具体原因，记录成本后再决定架构或模型实验。

代码修复按 [AGENTS.md](../../AGENTS.md)、[质量手册](../runbook/quality.md)及[当前 CI](../../.github/workflows/test.yml)执行受影响检查；跨模块或检索链路变化运行完整离线检查，实际框架测试须具备独立环境。前端变更须进行脚本语法检查及受影响页面流程验证。文档交付仅核对内容、链接和 Git 差异，不将历史测试结果作为本轮验证。

## 7. 交付、证据保存与后续决策

执行时在 Git 忽略的 `output/migration/reliability-review-<执行日期>/` 保存材料快照、冻结清单、原始回答、逐题核验、试用反馈和对照报告；创建后先检查忽略规则。公开报告仅保留必要的脱敏问题描述、汇总结果与证据索引；不提交人员身份/联系方式、原始访谈、数据库或包含个人信息的案例副本。

最终交付四项：

1. **事实核验报告：** 范围、复核方法与身份、逐题支持性/完整性/引用结果、歧义及评价限制。
2. **试用反馈报告：** 实际使用者背景、任务、核验过程、具体意见；无人参与则明确未执行及补齐责任。
3. **修复与复验证据：** 问题到提交的映射、工程检查、冻结回归与保留集结果、有效/无效配对及未知用量。
4. **下一步决策：** 未通过则围绕剩余问题继续修复；事实核验通过但无人试用则补齐人工反馈；两者完成后再检查既有 G2/E07 条件，不直接进入生产切换。

本轮完成的价值是取得可追溯的质量证据和可执行的使用者反馈。完整卷宗能力、独立专业终评、生产容量及 E12～E20 后续阶段继续按既有计划单独验收；两条历史 unknown 继续保留未决责任。
