## 工程和部署约束

- Node 24.22.1、pnpm 11.25.0 可由本机现有环境提供，版本命令已实跑；过去“缺少包管理器”的阻塞已解除，依赖安装/构建仍按实际检查记录。
- Next.js、React、TypeScript 使用精确版本与 `pnpm-lock.yaml`；前端构建不依赖在线字体和 CDN。框架版本只在显式升级时变化。
- FastAPI OpenAPI 通过隔离临时目录导出；HTTP 请求载荷类型从契约生成，SSE 的事件内容与顺序另行校验。后端未声明响应模型的接口需要在组件边界验证返回数据，不能把 TypeScript 断言当作运行时校验。
- 开发入口为 Next.js（仅监听 127.0.0.1），通过固定 `LEXVAULT_API_ORIGIN` 转发 `/api/*`；只允许操作员配置上游，不能由浏览器请求指定目标。
- **经 Next.js 开发代理必须配置 FastAPI token 模式**，使用现有 HttpOnly 会话或显式 Bearer 身份；不自动生成管理员身份、不清除代理标记来绕过本机模式的拒绝。正式静态部署由浏览器直接访问同源 FastAPI，原 local 模式仍可用于直接回环访问。
- SSE 原样传递流、取消信号与终态，不把完整响应缓冲后再发；不缓存 API、文件和问答结果。
- A11.4 已将 `run.sh`、Docker 和 `/`、`/mobile` 切换至静态构建。运行时仅 Python，Node 只用于开发/构建；旧 `/assets/*` 正式路由已移除，归档源码继续接受原语法与回归检查。发布与回滚见[运行手册](../runbook/frontend.md)。

## 前端检查

在 `frontend/` 执行 `pnpm install --frozen-lockfile`、`pnpm contract:check`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm build:static`、`pnpm test:e2e`；依赖审计执行 `pnpm audit`。契约变更时先 `pnpm contract:generate` 并审查差异。

以上是验收要求；实际通过记录另附实施报告。后端完整离线门禁和已知语料失败继续独立报告，不用前端构建通过替代。
