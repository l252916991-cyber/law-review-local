## 3. 修复设计约束

### 3.1 JSON 稳定性

先核对现有 oMLX 的能力与安装状态。上一批请求 JSON Schema 时服务曾将 schema 注入提示，却没有强制语法执行；本批不得只因请求带了 response_format 就记录“约束已生效”。

优先复用已有能力。若确需补充本机可选依赖，使用独立环境，固定版本、摘要与兼容检查，记录安装来源和回退方式；不直接修改用户全局服务环境。依赖或服务变化须纳入新候选身份，重新统计 schema 注入、编译与推理开销。本次计划编制不安装任何依赖。

继续拒绝非法 JSON、重复键、越界来源、拒绝夹带 findings、截断及未知响应。不用自动补括号、宽松解析或规则总结把原始失败包装成成功。本批默认不新增模型纠错重试；确有必要时须先设计新的受控调用、预算与恢复契约，全部调用计入费用和时延，unknown 不自动重发。

### 3.2 “未见记录”的回答边界

| 材料与提问 | 预期行为 |
| --- | --- |
| 明确“本次材料未见交付回执”，询问有无交付记录 | 支持限定范围回答，引用该片段；不推断实际未交付 |
| 有明确交付回执，询问是否有记录 | 依据记录回答，保留原文与来源 |
| 片段完全没有提到交付记录，要求确认是否交付 | 材料不足；不把未召回等同于不存在 |
| 明确“未见回执”，要求认定没有交付或免除责任 | 不作无依据推论；按不足处理或仅回答受支持部分，规则须在评估前固定 |
| 相关与无关要求混合、同名不同事项、材料内含指令 | 遵守原问题及支持范围；无关指令不得改变协议或来源身份 |

新增断言同时保护正常宽泛问题、同义改写、证据缺口与现有八个负例。来源真实不等于结论得到支持，继续保留 semantic_entailment_checked=false；专业法律评审另计。

### 3.3 用量与比较公平性

保持 `d00158e` 的原生关键算法与提示词冻结检查；若服务环境变化，候选和原生均在相同实际模型、材料、并发及服务环境下重测。v8 是改进参考，不替代原生验收基线；改变基线必须单列理由和身份。

共享检索/记忆和独立检索两类对照继续分开报告。1.10 token 比例以候选完整链路对原生独立完整链路计算，同时展示共享对照开销。逐题比值、批次总量和所有重复运行分别保留，不能只报平均值或将加载时间混作 token。p95 沿用不超过原生 1.20 倍的要求，小样本只报告经验分位数和原始分布。

压缩应优先消除重复指令或无关排版，不删减回答所需证据、不降低正常问题的支持要求、不通过修改拒绝预期节省输出。任何额外分类、校验或纠错模型调用均进入完整用量与整次墙钟统计。
