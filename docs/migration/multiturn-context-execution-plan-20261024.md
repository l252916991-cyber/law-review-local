# 多轮追问与上下文利用：下一步执行计划

日期：2026-10-24（北京时间）。编制基线：`540b2ad`，工作区初始干净。状态：**待执行；本次仅制定计划，未改业务代码、未运行模型评测。**

本计划承接[回答可靠性与使用者核验计划](reliability-review-plan-20261024.md)，围绕一个可验证的场景推进：使用者先问某份合同，再问“它的付款期限呢”，系统能识别前文对象、重新检索合同原文、给出带本轮引用的回答；对象不明确时请求澄清。

## 2. 范围与用户可见行为

首个可交付切片为普通聊天：同一案件、同一可访问且未归档会话内的连续追问。随后复用同一能力接入原生 Agent 与 LangGraph，并处理后台提交与恢复；每个入口分别验收，不用一个入口的通过覆盖其他入口。

| 用户场景 | 预期行为 |
| --- | --- |
| 先问“甲公司采购合同的签署方”，再问“它的付款期限呢” | 指向前文唯一合同，重新检索付款条款，正文说明对象并附当前资料引用 |
| “不是这份，是补充协议”或“改看乙公司的合同” | 当前明确更正优先，重新解析对象；不得沿用旧对象继续回答 |
| 前文谈过两份合同，再问“它的付款期限呢” | 若无法唯一确定，列出必要选项请求澄清，不自行选相似度最高者 |
| 历史回答写“30 天”，当前原文为“验收后 60 天” | 依据当前原文回答，说明历史内容需更正；不得把旧回答当支持证据 |
| 新建会话或切换案件后直接问“它呢” | 不继承另一个会话的指代对象；仅凭同案草稿命中也不能默认为前文 |
| 旧引用对应资料已删除、变更或不可访问 | 不沿用旧编号/旧页内容；校验当前可见材料，再检索、澄清或说明资料不足 |

本轮以资料事实问答为对象；不据此声称法律适用正确、完整卷宗能力或专业业务验收通过。事实质量及人工试用仍按前述可靠性计划收集证据。

## 3. 目标处理流程与上下文契约

处理顺序：**校验案件与会话访问 → 冻结历史快照 → 解析提问对象 → 重新路由与检索 → 必要时澄清 → 基于当前原文生成 → 校验引用并保存。** 澄清可以发生在解析后或检索验证失败后；不得生成一段猜测事实后再补一句“请确认”。

明确区分“有据回答”“请求澄清”“资料不足”三类结果。澄清消息可以作为会话轮次保存，用于接收用户下一轮选择，但不得伪装为已验证事实或写入案件草稿记忆；单独定义其输出契约，不能为允许无引用澄清而放宽事实回答的引用校验。

### 3.1 历史读取与边界

1. 从服务端数据库按受信的案件、会话和访问主体加载历史，不接受客户端传入的任意历史正文作为已保存上下文。沿用现有访问控制，不能把可填写的 `user_name` 当作授权依据。
2. 显式提供但不存在、跨案、无权访问的会话 ID 拒绝请求；归档会话返回现有只读冲突语义。只有未提供 ID 才创建新会话。此行为变化同步 API 文档与前端错误提示，并补兼容性测试。
3. 初始窗口建议最近 **4 个完整问答轮次、合计最多 4,000 字符**；排除当前请求、失败或未完成轮次，按消息 ID 固定顺序。超预算按完整旧轮次淘汰，记录截断原因；被淘汰的对象不可继续猜用。以上是待评测的初始参数，冻结后不得按失败题临时改值。
4. 保存历史消息 ID 截止点、摘要哈希、策略版本与对象来源。并发请求固定各自接收时可见的历史；提交消息仍保证成对写入。生成期间发生删除、归档或撤权时，提交前再次检查，失败时不写入成功回答。
5. LangGraph 恢复和后台重试复用本次冻结的上下文身份，重新验证访问与资料有效性；状态变化时明确停止或要求新请求，不把新历史拼进旧运行。保留已有幂等与不重复模型调用语义。

同步 Agent 入口也须接入统一的会话读写，而不只是增加请求字段；普通聊天、同步 Agent 和后台任务均返回实际会话 ID，按运行/请求身份确保同一问答轮次只保存一次。

### 3.2 对象解析与检索

引入共享的上下文准备组件，输出原始问题、规范化检索问题、候选文档/对象 ID、解析状态（明确/已解析/需澄清）、依据消息 ID、历史快照身份及预算使用。名称和数据结构在实现阶段确定，原始问题始终保留。

- 无省略且对象明确的问题直接使用，不必为每次请求增加模型调用。
- 有省略时，优先使用当前明确指示和会话内可验证的对象；确需模型解析时，只允许从授权候选对象中选择或返回需澄清，禁止让改写过程补造金额、期限、法律结论。
- 使用解析后的问题执行路由、检索与相关专家处理，原始问题供最终回答及审计对照；防止只改审校提示、检索仍搜“它”的半接入。
- 既有文档 ID、历史引用只作定位线索，必须重新核对案件、访问范围、资料版本与当前内容。唯一合同问题可限定该资料；多资料比较须保留所有相关对象，不能因过滤丢失补充协议或冲突材料。
- 当前检索未找到所问条款时，输出限定范围的不足或澄清；不能回退为引用历史回答中的事实。`use_llm=false` 时也不能借历史补造答案；无法可靠解析就明确澄清。

### 3.3 模型输入与草稿记忆

模型输入分开组织：系统规则、当前问题与已解析对象、有限会话历史、可选草稿线索、当前卷宗片段。历史、草稿和卷宗文本均作为不可信数据；其中的“忽略规则”等语句不能提升为 system/developer 指令。历史 assistant 内容仍是待核验输出，不授予事实权威。

本轮默认先只启用会话历史。草稿记忆作为单独实验开关：最多 3 条、合计最多 2,000 字符，与会话历史合计最多 6,000 字符；记录实际 token，字符上限不等同模型 token 预算。优先保证系统规则、当前问题、必要原文与输出空间，超限先移除草稿，再移除旧轮次；仍不足时明确失败或缩小问题，不静默截断关键条款。

草稿仅帮助提出待核验线索，保留 `source_run_id`、草稿 ID、信任标记和排除原因，不分配本轮 `[资料N]` 引用编号。现有草稿未提供充分有效性信息时保守排除，不根据旧答案文本推定来源仍有效；与原文冲突时以当前核验结果为准。删除会话是否应同步删除其派生记忆需明确数据生命周期与关联关系，未落实前不允许被删除会话的内容经草稿绕回上下文。

`call_local_llm` 与 `CriticAgent.run` 的扩展保持旧调用默认无历史兼容；原生与 LangGraph 使用同一准备/格式化逻辑。更新提示身份与 provenance，记录“历史是否启用、对象如何确定、哪些线索被使用/排除”；日志不额外复制完整案件正文。最终引用只来自本轮检索片段，重新编号并逐项对齐页面资料卡。

## 5. “有历史／无历史”对照设计

主实验比较 **A：不读取历史、不注入草稿** 与 **B：读取同会话历史、不注入草稿**。附加消融比较 **C：历史＋草稿线索** 与 B。A/B/C 使用同一实现中的开关、相同模型/参数/材料快照/问题，明确记录 A 与旧提交基线的差异；原始无历史版本另外保留用于单轮回归。

冻结至少 **12 组会话、24 道追问题**，每组包含前置轮次和两个追问。覆盖下表，并将至少 4 组会话（8 道追问）作为首次评测前封存的保留集；其余为开发集。单轮另设至少 8 道对象明确的问题检查退化。重复运行不增加独立题数。

| 覆盖类别 | 追问题最低数 | 核心预期 |
| --- | --- | --- |
| 单一对象省略、付款期限/金额/条件追问 | 8 | 定位正确对象，给出完整事实和原文引用 |
| 多合同歧义及用户更正对象 | 4 | 该澄清时澄清，更正后切换正确 |
| 历史错误、旧草稿与当前材料冲突 | 4 | 不复述错误，不提升草稿可信度 |
| 新会话、跨案、归档/删除/撤权 | 4 | 明确拒绝或澄清，零串案与不可访问数据使用 |
| 长历史截断、历史注入、无原文支持 | 4 | 预算受控、无指令越权，无依据不作确定性回答 |

另以确定性集成测试覆盖矩阵未逐一包含的并发、后台重试、恢复、资料更新与重复写入边界；题量不足以替代这些工程检查。

评测分两部分：

1. **冻结历史的配对实验（主结果）。** 从同一历史/草稿快照启动每个分支，关闭评测中的新增记忆写入或使用独立副本；A 不读取快照，B 仅读取会话历史，C 再读取草稿。材料、用户问题完全一致，各组交错执行，禁止前组输出污染后组。不同检索结果是上下文改进的预期效应，不强行共享检索片段。
2. **端到端多轮流程（补充结果）。** 每个分支从空白隔离会话开始，实际运行前置问答再追问；记录错误累积。前轮回答不同的结果不与冻结历史实验混为同一因果结论。

逐题记录对象解析、必答事实、正文支持性、当前引用定位、澄清是否恰当、原始输出、真实调用数、token、端到端时延及核验者。时延包含历史读取、解析/改写、检索与最终生成；改写模型调用也计入成本。报告原始分布、p50/p95、总量和逐题差异，小样本不宣称统计显著或普遍业务增益。

## 6. 放行标准与回退

- **正确性：** 冻结的可唯一解析题须全部定位正确，必答项完整且被当前原文支持；歧义、无来源和不可访问题须按预期澄清或拒绝。跨案读取、历史注入越权、虚构事实、旧引用冒充当前引用、重复副作用均为零容忍。
- **历史增益：** B 在依赖前文的可回答题上，正确且有原文支撑的答案数须高于 A；对象明确的单轮题不得新增事实/引用错误。未取得增益则记录失败原因，不称为上下文工程效果已验证。
- **草稿增益：** C 相对 B 需有逐题可解释的新增收益，且不增加事实错误、误拒或越权；否则维持草稿注入关闭。
- **性能：** 本轮先冻结探索预算为 B/C 相对 A 的批次总 token ≤1.50、端到端 p95 ≤1.30，并报告每题调用开销；这不是既有 G2 门槛的替代。超限则优化或保持实验关闭，不靠截断关键证据通过。若申请 G2 状态变更，仍须另外满足既有逐题/总量 1.10、p95 1.20 等完整要求。
- **证据：** 实际用量缺失、无效配对、模型失败分别列出；未知不得填零，补跑使用新身份。保留集见题后调参即转开发集，重设保留集再验证。
- **用户流程：** 实际进程加载最终代码后，验证连续追问、引用跳转、澄清后续问、重新打开会话、切案/新建、归档，以及 Agent 后台完成/恢复。原文事实复核与法律背景使用者试用分别记录；无使用者时保留未执行，不能代签专业意见。

新增能力设置可回退的策略开关，关闭后不读取或注入历史/草稿；无上下文且对象不明时澄清。回退保留已保存消息与审计，不恢复跨案或归档会话的旧宽松行为。新增持久字段需兼容旧记录，历史运行无快照时显式标记无上下文，不能用当前历史重建旧运行冒充恢复。

## 7. 验证与最终交付
