## 1. 本轮要回答的问题

1. 同一模型、同一来源和相同调用预算下，多专家结构化交接是否改善回答？来源交叉核对与分歧保留这一组合带来什么增量变化？
2. 改善发生在哪些题型，增加多少输入 token 和耗时，哪些题型没有收益或出现退步？
3. 来源变化、节点失败、模型不可用时，系统如何留下诊断、拒绝复用过期结果并交给人工处理？
4. 面试官能否根据说明重建环境、运行合成样例，并核对简历中每一项指标？

本轮优先补效果证据和演示。新增独立 LLM 专家、自主反思循环、更换框架、多实例部署和新业务模块不在范围内；后续仅依据已发现的失败提出必要改进。

## 4. 三组对照协议

### 4.1 实验组定义

三组均在新的隔离合成库中运行，以**相同冻结检索上下文、相同问题、相同模型、同一份回答要求和一次最终生成调用预算**为主对照。模型历史与记忆为空；主实验统一关闭自主工具循环及模型回退，保留失败记录。实际产品的工具与回退能力另做端到端验证，不混入受控消融的因果结论。

| 组别 | 模型输入与生成后处理 | 要测量的变化 |
|---|---|---|
| A：基础 RAG | 原始检索上下文与问题，不附专家 JSON | 基础参考表现 |
| B：结构化交接 | A 的全部信息，加原始专家结构化发现 | 结构化整理是否改善回答 |
| C：交叉审校 | 模型输入在 B 上增加来源核对与跨专家待补信息；生成并校验原始回答后追加分歧保留附录 | 交叉信息与确定性保留机制的组合增量价值 |

三组保留相同案件授权、输入来源绑定、端点管控、输出引用校验、超时和总量限制。所有组均先校验模型原始回答，附录不能挽救不合格输出；保留不可信草稿标记及法条/案件命名空间隔离，禁止长期记忆读写。B 不注入 `source_checks`、`upstream_review` 等衍生审校信息；相关控制只存在于隔离实验适配层，不增加可绕过正式校验的产品开关。C 也不能宣称逐个专家独立进行了模型推理。

每组记录实际提示、上下文和输出摘要及各节点输出。预期答案、评分标签和 Judge 结果只用于评价，不进入生成上下文。输入 token 的变化是协作机制的成本，应计入结果；固定同一硬上限，超限明确失败，禁止静默截断。配置可复现的采样参数，记录后端不支持 seed 等情况，不承诺跨设备逐字一致。三组实验只测量 C 中两项机制的组合增量；若要区分各自的因果贡献，另行预注册拆分实验。

`scripts/run_answer_eval.py --live` 当前只采集普通 `services.chat` 路径；不能直接作为三组驱动。P1 应复用现有采集/计量组件，补齐缺少的适配层及回归。`app/model_comparison.py` 的固定摘要门禁继续保留；若修改其受检算法，显式登记新身份，旧结果不被覆盖。

### 4.2 数据、轮次与预算

- 开发回归：复用 v2 的 60 题，类别为正常 30、候选矛盾 10、资料不足 8、无关 4、缺法条 4、问题注入 4；完整保留现有题目与失败。
- 保留集：建议新增 **6 个独立案例、每案 4 题，共 24 题**，使用完全合成或获准使用的公开材料。与开发案件按来源及案件划分，不能仅改同案问题措辞；预先冻结来源、预期、评分标准和摘要。
- 预检：从开发集预先指定正常、资料不足、矛盾各一题，三组各跑一次，先确认真实推理、来源、用量和超时记录有效。
- 主实验：开发集三组各一轮用于定位问题；候选冻结后，保留集三组各重复三次，采用预先登记的轮换顺序，降低缓存和模型加载顺序影响。保留集一旦用于调参，即转为开发数据，需另建未见过的保留集。
- 规模示例：预检 9 次、开发 180 次、保留 216 次，共 **405 次计划生成**，不含 Judge、必要重跑及演示。此为工作量估算，不是调用授权、真实用量或费用；执行前按实际上下文长度和服务能力登记总 token、时间、费用（若有）及停止上限。
- 先做小规模预检；资源不足时保留失败并调整下一批方案，写明变化，不能降低模型资源保护。远端或付费调用需已有明确的数据与预算授权；不将真实卷宗发给模型作为默认选项。
- 所有尝试写入同一批次清单。传输失败、非法响应、超时、规则降级、未尝试和未知调用分别统计；不能只选成功样本计算整体成功率。

### 4.3 指标与评分边界

| 指标层 | 记录方式 | 可作出的结论 |
|---|---|---|
| 工程有效性 | 实际模型调用、输出契约、来源一致、缺失分支、恢复和失败记录 | 流程是否按设计执行 |
| 回答质量 | 要点完整、无据断言、引用是否支撑、可答/应拒答分别评分 | 在明确样本和评审方法下的回答表现 |
| 分歧保留 | 模型原始回答与最终含附录报告分别计数、评分 | 区分生成质量与规则附录保留率，不能把附录补齐算成模型推理变好 |
| 效率 | 每题输入/输出 token、调用数、耗时中位数与分位数、模型加载时间 | 当前设备与批次的成本和延迟；小样本 p95 不作为 SLA |
| 稳定性 | 重复轮次的通过/失败、答案变化、降级与未知用量 | 固定配置下观察到的波动 |

确定性词面评分、模型 Judge、开发者自审和独立人工评分分别报告。对可答题报告完整性与无据断言，对不可答题报告正确拒答与可答题误拒；不以一项总分掩盖差异。无价格时费用为未知，本地 token 不是商业账单，也不等于零成本。

盲审预先抽取至少 20 道分层题目，对三组答案隐藏组别并随机呈现，预先规定从重复轮次取样的方式；答案、题目和独立来源均绑定摘要。复用现有盲审流程，但三组配对与多案件输入需经 P1 适配验证。Judge/人工一致性沿用至少 20 个有效匹配标签的合同；缺人工、Judge 不可用或 κ 无定义时明确留空。开发者不能替独立审核人填写标签，无专业复核不声称法律业务准确率。

以同题配对差异、每类结果、样本数及各轮波动为主要报告，不预设“必须提升 X%”。若计算区间，按案件聚合/重采样并说明仅 6 个保留案例的限制；不把同案多题或重复回答当作大量独立案件。若 C 没有收益，照实总结适用边界，作为设计取舍材料。

## 5. 演示与工程收尾

### 5.1 三至五分钟演示

演示使用冻结合成案件和真实模型响应，依次展示：材料导入 → 提问及来源定位 → 专家结构化发现 → 候选矛盾/待补事项 → 人工查看 → 报告复核与指定版本导出。选择场景时标明它是展示样例，不用精选视频代替全量评测。

另保留一个短异常演示：修改来源后拒绝恢复旧分析，或在独立进程重启后复用已完成结果。记录恢复前后运行标识、调用数及保存结果；不为演示强行终止用户现有服务。模型不可用时的降级必须标明，不能用固定答案替身冒充真实模型。

核对后端加载路径、代码提交、前端输入与构建摘要、模型身份和合成来源摘要；保留原始录制、日志及成片清单。必要的剪辑或加速应注明，实际耗时以测量日志为准。展示可观察的节点输入输出、工具轨迹和检查结果，不要求或展示模型隐藏思维链。

### 5.2 可复现运行与发布边界

1. 复用项目固定 Python/Node/pnpm 版本和锁文件，在新目录重建；按发布允许清单打包，不含运行数据库、个人数据、凭证、模型权重和原始私有报告。
2. 依 [AGENTS.md](../../AGENTS.md)执行与修改范围相符的检查。新增跨模块实验驱动时跑现有完整离线范围；框架进程测试使用独立 Python 3.12 环境，前端修改按现有完整前端门禁执行。
3. 已有 G1 结果先核对代码、平台、资产和报告身份，再决定是否复用；不能按旧状态表重复宣称未执行，也不能把历史通过直接移到新版本。
4. 求职展示至少验证一种实际安装与启动路径；Docker 仅在实际构建与启动检查通过后声明可用。G1 保留原发布要求，不因选择本地演示而取消容器门禁或真实资产问题。
5. 代码未变化且同身份检查已通过时不无故重复长测试。正式发布、推送、真实库迁移和外部材料上传仍按相应授权与门禁执行；本计划不自动开展这些动作。

**求职展示版完成**要求：协议与实际执行一致；真实模型对照可复算且包含负结果；当前版本真实流程演示通过；至少一种安装路径复现成功；简历和面试材料的全部声明有对应证据。人工评价缺失时只交付工程/模型裁判阶段结果，不写“独立质量验收完成”。本项目定位与统计限制应随材料一同交付。
