# 多人协作首版改进计划书

- 编写日期：2026-10-27（Asia/Shanghai）
- 代码基线：`580c5b7 feat(agents): 实现来源绑定的专家交接与交叉审校`
- 状态：**执行中**。第 1–3 节为核对结论，第 6–10 节为工作包与验收口径，第 12 节随实施更新。
- 定位：把项目收敛为**一家律所内部使用的协同阅卷系统**（单组织、单实例、受控设备）。本计划不再扩展 AI 能力，主线是多人分工、责任闭环与交付可信。

## 1. 结论

当前版本已经具备协同阅卷的骨架：案件隔离、`view/edit/approve/export/manage` 五类权限、审批归属、导出包哈希与清单。但**协作语义尚未闭环**：权限靠环境变量维护、没有人员任务、并发保存会静默覆盖、交付仍是一个 `final=true` 开关而不是报告签发流程。

因此首版的范围不是"再加功能"，而是把下面五件事做实：

| 主线 | 首版必须达到 |
|---|---|
| 成员与案件分工 | 管理员可增减成员、调整案件权限、指定负责人；人员离开后可明确撤权并终止会话 |
| 人工任务闭环 | 阅卷/核证/补证可指派到人、设期限、提交与退回，并有待办视图 |
| 并发与审计 | 两人同时改同一条证据不会静默覆盖；修改可查到操作者、时间与前后值 |
| 报告复核与签发 | 报告有草稿/待复核/退回/批准状态；导出绑定已批准版本与当时的材料快照 |
| 部署与运行保障 | 身份、权限、模型、OCR、容量、备份恢复、故障提醒有可执行验收清单 |

另有四项已确认的正确性缺陷必须在协作功能之前修掉（见第 4 节），否则多人使用只会放大错误。

## 2. 范围

**做**：单律所、单实例部署下的成员管理、案件分工、人工任务、并发保护、报告签发、材料纠错与可恢复交付。

**不做**（本版明确排除，后续按需再议）：客户与商机管理、收费与工时、电子签约、完整办案日历、跨所多租户、多实例高可用、在线热备与异地复制、AI 能力继续扩展。

**沿用不推翻**：SQLite 单库、FastAPI + Next.js 静态构建、`local`/`token`/OIDC 三种身份模式、证据审批失效规则、导出包结构与 `清单.json`、现有离线测试与 CI 门禁。

## 4. 已确认缺陷（P0，先修）

| 编号 | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| D1 | 证据保存无版本条件 | `app/main.py:1057` 直接 `UPDATE evidence ... WHERE id = ?`，无版本或 `updated_at` 条件 | 两人同时编辑，后保存的人静默覆盖前者；审批人记录也可能被覆盖 |
| D2 | 流水超过 500 条时统计与导出不完整 | `app/services.py:1686` 导出取 `limit=500`；`app/services.py:215`、`app/services.py:229` 同样只算前 500 条 | 大额案件导出缺失流水，`清单.json` 的 `transaction_count` 与哈希覆盖范围不符 |
| D3 | 案件信息不可修改 | 无 `PATCH /api/cases/{id}`，前端无入口 | 录错案号/当事人只能重建案件，破坏案件 ID 与审计连续性 |
| D4 | 材料纠错不完整 | `app/main.py:827` 仅目录字段；`app/main.py:843` 审计只记文件名 | OCR 错字无法修正（直接污染检索与引用）；纠错无前后值、无失效传播 |
| D5 | 人员停用不终止会话 | `app/security.py:56` 每次请求重读配置，但身份平台停用不发信号 | 离职人员最多可继续使用 8 小时 |

## 5. 目标模型

### 5.1 角色与案件分工

| 角色 | 权限 | 说明 |
|---|---|---|
| 管理员 `admin` | 全部 + 成员管理 | 至少保留一名；不可移除自己 |
| 承办律师 `owner` | view/edit/approve/export | 案件负责人，可指派本案件任务 |
| 复核律师 `reviewer` | view/approve/export | 只能确认与退回，不能改内容 |
| 助理 `assistant` | view/edit | 导入、校正材料、整理证据，不能确认或导出 |
| 只读 `viewer` | view | 观察、审计 |

案件级角色落在 `case_members(case_id, member_id, role)`，与全局权限取交集（管理员除外）。成员与令牌绑定后，撤权即删除绑定并清理该成员会话。

### 5.2 人工任务状态机

```
待处理 → 进行中 → 待复核 → 已完成
   ↑        ↓        ↓
   └──── 已退回 ←──────┘（退回必须写原因）
```

任务字段：所属案件、类型（阅卷/核证/补证/复核/归档）、标题、说明、指派人、期限、关联证据或文档、创建人、关闭人。每次状态变化写 `review_task_events`（操作者、时间、原因、前后状态），不覆盖历史。

### 5.3 报告签发状态机

```
草稿 → 待复核 → 已批准 →（材料变更）→ 已作废
          ↓
        已退回 → 草稿（保留退回原因）
```

报告记录绑定：模板、证据版本集合摘要、材料内容哈希、编制人、复核人、批准时间。`/export?final=true` 只在存在**已批准且依据未失效**的报告时放行，导出包写入报告版本号与批准人，取代当前的单一 `final` 开关。

## 6. 工作包

### W1 成员与案件分工（P1）

- 数据：`members`、`member_tokens`、`case_members`；环境配置保留为启动引导（首个管理员）。
- API：成员增删改查、令牌轮换/吊销、案件成员与角色调整；禁止删除最后一名管理员、禁止自降权。
- 会话：成员停用或令牌吊销时删除其 `auth_sessions`，并写 `security_events`。
- 界面：设置页"成员与权限"，案件页"分工"。
- 验收：撤权后旧会话立即 401；被移出案件的成员访问该案件返回 404；案件负责人可指派任务但不能加人。

### W2 人工任务闭环（P1）

- 数据：`review_tasks`、`review_task_events`。
- API：建任务、改指派人/期限、提交、退回（含原因）、完成、关闭；个人待办列表。
- 界面：案件工作台任务区 + 全局"我的待办"。
- 验收：任务可指派到不同角色；退回必须填原因；期限到期在待办中标红；交接后原责任人不再有操作权，历史仍可查。

### W3 并发与审计（P0）

- 证据、文档目录、案件信息增加 `version` 整型；更新接口接受 `expected_version`，不匹配返回 409 并附当前记录。
- 审计记录改动字段的前后值（脱敏、限长），不写正文全文。
- 前端在冲突时提示"已被他人修改"，刷新后再改，不自动重试覆盖。
- 验收：两个客户端同时保存同一条证据，第二个得到 409；`audit_log` 能查到操作者、字段与前后值。

### W4 报告复核与签发（P2）

- 数据：`case_reports`（版本、状态、依据快照、编制/复核/批准人）。
- API：创建草稿、提交复核、退回、批准、作废；列出历史版本。
- 导出：`final=true` 必须绑定已批准报告，材料或证据版本变化后自动作废并要求重新复核。
- 验收：未批准报告不能正式导出；批准后修改证据，再导出被拒绝并提示重新复核。

### W5 部署与运行保障（P2）

- 可执行验收脚本：身份模式、令牌强度、允许主机、模型端点、OCR 依赖、数据目录容量、备份可恢复性逐项输出通过/失败。
- 运维手册补充：成员变更、离职撤权、备份恢复演练、故障提醒渠道。
- 验收：在目标设备上跑一遍脚本全绿，并完成一次"备份 → 清空 → 恢复"实测。

| 阶段 | 内容 | 退出标准 |

## 8. 数据与迁移

- 只做增量：新增表 + `ALTER TABLE ... ADD COLUMN ... DEFAULT`，沿用 `app/db.py` 的有序迁移与 `user_version` 拒绝未来 schema 的策略。
- `version` 列默认 1，历史行不需要回填；更新语句 `SET version = version + 1, ... WHERE id = ? AND version = ?`。
- 删除成员不物理删除历史记录，改为 `active = 0` 并保留审计与任务历史。
- 导出 `清单.json` 增加 `report`、`evidence_versions`、`schema_version` 提升说明，旧包仍可读。

## 9. 验收用例

至少用管理员、承办律师、复核律师、助理、只读五个身份各跑一遍：

1. 未获授权人员无法查看、下载、导出案件（列表、详情、原文页、源文件、导出五个入口）。
2. 两人同时修改同一条证据，第二个保存得到 409，界面提示刷新，不静默覆盖。
3. 修改已确认证据内容后状态回到待复核且 `approved_by` 清空；材料原文纠错后相关证据同步失效。
4. 任务可分派、退回（带原因）、完成；交接后原责任人不能继续操作。
5. 报告未经批准不能正式导出；批准后材料变更，导出被拒绝并提示重新复核。
6. 流水超过 500 条时统计、图谱、导出条数与金额一致，`清单.json` 的哈希可复算。
7. 备份后清空数据目录再恢复，案件、证据、附件、导出包可读且哈希一致。
8. 成员停用后其会话立即失效（401），案件移交后新负责人可见、原负责人不可见。

## 11. 风险与非目标

| 风险 | 应对 |
|---|---|
| 成员数据落库后与环境配置双源冲突 | 环境配置只做启动引导，落库后以其为准；冲突时启动失败而不是猜测 |
| 版本冲突导致律师反复重试 | 冲突响应返回当前记录与差异字段，前端只提示不自动重试 |
| 报告签发被绕过 | 导出侧校验，不依赖前端按钮状态 |
| 单人 SQLite 并发写锁 | 明确单实例、单写者；不接受多实例部署承诺 |
| 任务与报告状态膨胀 | 只保留状态事件，不复制正文；关闭后只读 |
