# 利益冲突检查

律所受理业务前要查一遍：本所是否正在或曾经代理过对方。案件登记当事人后，系统用这些当事人检索全所其他案件（包括已归档的，也包括设了隔离墙的）。命中后案件进入“待审批”，合伙人放行前不能开展工作。实现见 `app/conflicts.py`。

## 登记当事人

| 字段 | 说明 |
| --- | --- |
| `role` | `client` 委托人、`opposing` 对方当事人、`related` 关联方（控股股东、实际控制人、担保人等） |
| `name` | 名称，至少两个有效字符 |
| `former_names` | 曾用名，最多 10 个 |
| `credit_code` | 统一社会信用代码，18 位，可不填 |

```http
POST /api/cases                       {"title": "...", "parties": [{"role": "client", "name": "乙贸易有限公司"}]}
PUT  /api/cases/{case_id}/parties     {"parties": [...]}          # 整体替换并立即检查
GET  /api/cases/{case_id}/parties                                  # 当事人、当前状态与最近一次检查
POST /api/cases/{case_id}/conflict-check                           # 重新检查（例如别的案件改了当事人之后）
POST /api/cases/{case_id}/conflict-check/decision {"decision": "approve" | "reject", "reason": "至少 10 个字"}
```

建案时带上 `parties`，或者之后每次修改当事人，都会自动检查一次，每次检查单独留一条记录。界面：案件的“利益冲突与隔离”页可以登记当事人、查看命中、重新检查，管理员可在这里写明理由放行或驳回；检查未通过时，案件标题旁会显示“利益冲突待审批”。

## 什么算冲突

| 本案 | 其他案件 | 结果 |
| --- | --- | --- |
| 委托人 | 对方当事人 | 直接冲突 |
| 对方当事人 | 委托人 | 直接冲突 |
| 关联方 | 委托人或对方当事人 | 关联冲突 |
| 委托人或对方当事人 | 关联方 | 关联冲突 |
| 同一角色（以前也代理过这个委托人） | | 不算冲突 |

名称比对前统一全角半角、大小写，去掉空格和标点，再去掉公司名末尾的组织形式（股份有限公司、有限责任公司、有限公司、集团、公司）。所以“乙 贸易有限公司”和“乙贸易有限责任公司”算同一家。曾用名与名称交叉比对，统一社会信用代码相同时，名称不同也算命中。宁可多报，由人来判断：同名不同人、地名前缀不同（“北京甲科技”和“甲科技”）这类情况目前不会自动合并。

## 审批与限制

| 状态 | 含义 | 能否开展工作 |
| --- | --- | --- |
| 未检查 | 没有登记当事人（功能上线前的案件也是这个状态） | 能 |
| 未发现冲突 | 检查没有命中 | 能 |
| 命中待审批 | 有命中，等合伙人决定 | 不能 |
| 已放行 | 合伙人写明理由后放行，例如已取得双方书面同意 | 能 |
| 未获放行 | 合伙人驳回 | 不能 |

- **“不能开展工作”**指该案件的一切写操作都返回 409：上传、问答、证据、任务、报告等。查看不受影响。修改当事人、重新检查、作出决定、修改案件信息、归档和删除仍然可以做，以便处理冲突。这一限制在访问中间件里统一执行，新增接口不需要再单独处理。
- **审批人**：需要管理权限，并且不能是发起这次检查的人（双人原则）。理由至少 10 个字，与决定一起写入审计日志和安全事件。本机单人模式只有一个身份，允许自行决定，审计里会注明“未做双人复核”。
- **审计**：每次检查记录当事人数量和命中数量；每次决定记录决定人和理由。

## 谁能看到命中的哪个案件

命中详情会指向另一个案件，所以按查看人决定显示多少：

- 查看人有权访问那个案件：显示案件编号、名称、案号，以及对方的角色和名称。
- 那个案件设了隔离墙，或者查看人没有被分配到那个案件：只显示“存在冲突”、冲突类型、是哪一个本方当事人命中的，不显示是哪个案件。

检查本身用系统身份执行，能看到隔离墙内的案件，所以墙内的冲突照样会被查出来，只是墙外的人看不到细节。PostgreSQL 上，当事人表和检查记录表同样受行级安全约束。

## 证据

`tests/test_conflicts.py` 在两种数据库上运行：

- 不同组织形式、曾用名、统一社会信用代码、关联方都能命中；同一角色不算冲突；格式不对的当事人被拒绝（422）。
- 命中后写操作返回 409，查看仍可用；承办律师无权决定；发起检查的合伙人不能自己放行；理由太短被拒；另一位合伙人放行后可以正常工作；已经决定过的检查不能再决定一次。
- 驳回后保持锁定，改正当事人、重新检查通过后恢复。
- 没被分配到对方案件的律师只看到“存在冲突”，响应里不出现对方案件的名称。
- 对方案件在隔离墙后：照样查出冲突，墙外的人看不到细节，墙内的人能看到。
- 本机单人模式允许自行决定，审计注明未做双人复核。

## 边界

- 名称比对是规范化后的完全相等，不做模糊匹配，也不识别同一主体的不同简称。
- 每次检查都会扫描全所的当事人表，几万条以内很快；规模再大，需要把曾用名拆成单独的表并建索引。
- 律所已有利冲系统时，应当对接它，而不是两边各维护一份当事人名单。这一项属于计划书阶段 6 的系统集成。
