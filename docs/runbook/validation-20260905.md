# 2026-09-05 修复验收记录

本轮范围是 LexVault 改进清单 L01–L42，以及检查中发现的队列、权限、恢复、引用、评测与发布缺陷。逐项处理和边界见 [42 项映射](improvement-checklist.md)。真实案件、模型、历史报告均保留；Career Lab 不在本轮范围内。

## 功能与工程变更

- 保留原生 DAG 为默认，LangGraph 复用相同业务 Agent；专家并行后等待依赖，再做疏漏检测。SQLite checkpoint 支持失败续跑，运行/步骤/记忆/疏漏副作用幂等；补充并发恢复、错误案件与数据库作用域验证。
- 修复批量队列的 Redis pool/队列名不一致；上传按块 staging 并限制总量、数量和单文件大小；索引使用受限线程并发；按文件记录状态和导入键，失败后可追踪及恢复。
- 修复证据删除异常及 API 返回契约；完成证据标注增删改查；单次 Agent 任务后台执行、前端轮询并在刷新后续追。
- 统一模型配置与错误诊断；模型超时、原始引用不合格时返回可追溯规则答案。不合格答案及失败运行不得写入可召回记忆，历史 legacy 记忆不自动当作事实使用。
- 修复向量模型/版本/后端/维度切换的缓存身份和恢复重算；移除查询路径全量重建 FTS；RAG 评测绑定对应案件标准答案，以原文片段提供率命名 quote 指标，避免混称忠实度。
- 增加本机回环默认边界、token 身份和案件权限、HttpOnly cookie 登录、跨站 API/导出防护、Host 校验与认证操作审计。上传 HTML 或伪造 MIME 不能作为同源活动内容执行；外部响应不泄漏原始命令错误/敏感堆栈。
- 锁定依赖、补齐离线 CI/覆盖率/静态检查、结构化日志和环境模板。发布使用白名单；新增停写备份、校验、新目录恢复及固定 revision 的模型准备入口。

## 1,000 题真实模型结果及评分审计

Qwythos-9B-v2-4bit-mlx，20 类各随机抽 50 题，seed=42，temperature=0，max_tokens=900。完整任务说明在调用前传入；没有向模型传入参考答案。1,000 次实际调用已完成，总耗时约 1.55 小时。

| 请求完成 / 技术失败 / 空回答 | 1000 / 0 / 0 |

| 审计后的 lawbench-local-v3 混合均分 | **52.41%** |

审计修复了复合罪名内标点被拆开、正确格式的错误类别被误标解析失败的问题。v3 仅规范展示差异，并保留多余/未知标签的扣分；不做基于参考答案的近似匹配。7 题分数改变，全题均分下降 0.165 个百分点；原标记的 10 条解析失败修正为 0，错误类别仍按错误评分。原始 1,000 条回答、原报告和 checkpoint 保留，审计新增模型调用为 0。

按任务分层、同题配对的 10,000 次 bootstrap，均分差的 95% 区间为 **+33.47 至 +38.31 个百分点**（seed=42）。此区间只覆盖已保存回答的抽样变化，未覆盖模型重复运行、数据污染和评分器误差。

较弱任务仍包括法律咨询 20.11%、法条背诵 25.35%、纠纷焦点识别 26.00%、场景法律依据 29.25%。本轮改善来自完整任务说明与评分/提取协议修复，没有训练新模型，也没有证明这些弱项已经解决。

## 仍然保留的边界

SQLite checkpoint、token 权限和进程内后台任务定位为单机原型。双版本比较与恢复 API 仍同步响应，人工审批 interrupt、SSE、多实例 PostgreSQL、企业身份管理和静态加密未在本轮加入。

current-law 数据仍明确标记 WIP；240 条 RAG 合成题可做回归，不能替代经过授权的独立人工法律标注。本项目许可证、既有模型转换来源及公开发布授权不能凭代码修复补造。

历史 16 次双运行时实验核心结构等价为 8/8，但完整答案契约仅 1/8；其延迟受轮次和热机影响，本轮没有重跑这一真实模型对比。当前代码质量回归通过，不应据此改写历史实验的质量结论。
