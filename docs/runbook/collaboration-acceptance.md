# 多人协作部署与运行验收

适用范围：一家律所内部、单组织、单实例部署的协同阅卷首版。本文给出可执行的验收步骤与判定口径；不构成对真实案件试点、法律质量或等保合规的结论。

配套工具：[`scripts/collaboration_acceptance.py`](../../scripts/collaboration_acceptance.py)（只读检查）与 [`scripts/data_snapshot.py`](../../scripts/data_snapshot.py)（停写备份/恢复）。

## 1. 验收前置

1. 在目标设备上完成安装，确认使用仓库固定的 Node 版本（`frontend/.node-version`）构建静态界面。
2. 以 `LAW_REVIEW_AUTH_MODE=token` 启动，配置至少一个环境管理员令牌（部署引导），或先由本机模式创建目录管理员。
3. 首次启动会执行数据库迁移到当前 schema；旧库升级前先做一次停写备份。
4. 备份演练期间必须停止 API 与 worker：工具会显式要求 `--quiescent`，不会在运行中悄悄备份。

## 2. 只读检查

```sh
uv run --locked python -m scripts.collaboration_acceptance --data-dir /path/to/data
```

可选参数：

| 参数 | 作用 |
|---|---|
| `--require-ocr` | 缺少 PDF/OCR 工具或 `chi_sim`/`eng` 语言包时判为失败（默认仅警告） |
| `--multi-user` | 按多人交付验收：`local` 单用户模式改为失败，不再只警告 |
| `--backup-drill DIR` | 在 `DIR` 下执行备份 → 校验 → 恢复 → 完整性/外键/表计数/冻结工件核对；`DIR` 必须不存在 |
| `--quiescent` | 确认 API/worker 已停止，允许备份演练 |
| `--checkpoint-db PATH` | 实际的 LangGraph checkpoint 路径，透传给备份工具；有自定义路径时必须显式传入 |
| `--probe-model URL` | 显式探测模型服务 `/models`，不发送案件数据；不传则不访问网络 |
| `--model-id ID` | 要求 `/models` 列出该模型，缺失即失败 |
| `--json` | 机器可读输出，便于值班记录归档 |

只读保证：所有数据库都以 `mode=ro` 打开，路径写错直接判失败，不会新建空库。

判定：`PASS` 通过；`WARN` 需要知悉但不阻断；`FAIL` 阻断验收。存在任一 `FAIL` 时脚本退出码为 1。

### 2.1 检查项

| 检查 | 失败条件（节选） | 说明 |
|---|---|---|
| `python` / `sqlite` / `fts5` | 版本不满足或 FTS5 缺失 | 检索与页索引依赖 FTS5 |
| `document_tools` / `ocr_languages` | `--require-ocr` 时缺少工具或中文语言包 | 扫描件导入需要 |
| `free_space` | 剩余空间 < 512 MiB | < 2 GiB 时警告 |
| `database` / `integrity` | 数据目录或完整性检查失败 | 只读 |
| `schema_version` / `migration` | 低于当前 schema | 先启动一次应用完成迁移 |
| `auth_mode` | 非 `local`/`token` | — |
| `token_strength` | 环境令牌短于 32 字符且未显式开启回环逃生口 | 不打印令牌本身 |
| `allowed_hosts` | 含 `*` | 防止任意 Host 访问 |
| `administrator` | 无环境管理员且无启用的目录管理员 | 否则无人能管理成员 |
| `member_directory` | 缺少成员表 | 旧库未迁移 |
| `revoked_access` | 停用成员仍持有有效令牌 | 正常流程会撤销 |
| `case_assignment` | 有启用成员未分配案件 | 仅警告，适合按需分配 |
| `overdue_tasks` | 存在逾期未结任务 | 仅警告 |
| `report_basis` | 已批准报告的基线与当前材料不一致 | 仅警告；导出会拒绝 |
| `signing_freeze` | 已批准报告没有冻结正文（历史批准或未迁移） | 仅警告；这些报告不能正式导出 |
| `multi_user` | `--multi-user` 下仍为 `local` 模式 | 阻断，多人交付不能用单用户模式验收 |
| `model_endpoint` / `model_list` / `model_target` | 接口不可达、模型列表为空或缺少 `--model-id` | 阻断；`/models` 可访问不等于模型就绪 |
| `model_inference` | 恒为 `skip` | 推理与引用效果属于授权后的业务验收 |
| `backup_drill` / `restore_checkpoint` | 备份或恢复失败、checkpoint 未随包恢复 | 阻断 |
| `restore_integrity` | 恢复库 `integrity_check` 或 `foreign_key_check` 失败 | 阻断 |
| `restore_schema` | 恢复库缺表（旧 schema 或未迁移） | 警告并列出缺表，不因缺表中断演练 |
| `restore_counts` | 双方都存在的业务表行数不一致 | 阻断；新增系统表不要求机械等量 |
| `restore_artifacts` | 已批准报告的冻结正文目录、文件或摘要缺失 | 阻断；恢复后必须能预览与下载 |

## 3. 备份与恢复演练

```sh
# 停止 API 与 worker 后执行
uv run --locked python -m scripts.collaboration_acceptance \
  --data-dir /path/to/data --backup-drill /tmp/lexvault-drill --quiescent
```

脚本会：备份到 `DIR/backup` → 校验清单与哈希 → 恢复到 `DIR/restored` → 运行完整性/外键检查 → 比对双方都存在的业务表行数 → 核对已批准报告的冻结工件。缺失的表单列为 `restore_schema` 警告（旧 schema 未迁移），不会中断演练。恢复耗时写入 `backup_drill` 明细，作为恢复时间的实测基线。演练产物可保留为证据，但不得含真实案件材料对外流转。

恢复实例的真实启动与业务验证（登录、权限、任务、报告、下载）属于人工验收，脚本只覆盖数据与工件层；`scripts/data_snapshot.py restore` 产出的 `RESTORE_REPORT.json` 用于配置恢复进程的 `LAW_REVIEW_DATA_DIR` 与 checkpoint 路径。

恢复真实环境仍使用 `scripts/data_snapshot.py restore`，并在恢复后执行一次只读检查确认 `schema_version`、`integrity` 与行数。

## 4. 人工业务验收（五个身份）

用管理员、承办律师、复核律师、助理、只读各登录一次，按[计划书第 9 节](../history/migration/collaboration-first-release-plan-20261027.md#9-验收用例)执行：

1. 未授权人员无法查看、下载或导出案件。
2. 两人同时修改同一条证据，第二人得到冲突提示，内容不被覆盖。
3. 修改已确认证据或纠错原文后，相关证据退回待复核。
4. 任务可指派、退回（写原因）、完成，交接后责任明确。
5. 报告未批准不能正式导出；批准后材料变化，导出被拒绝。
6. 导出包内 `清单.json` 的记录数与哈希一致。
7. 备份后清空工作副本再恢复，案件、证据、附件可读。

## 5. 权限矩阵

服务端规则：**有效权限 = 成员权限 ∩ 案件角色权限 ∩ 案件授权**。案件角色只收窄成员权限，不会恢复已撤销的成员权限；管理员不受角色限制。界面按钮显隐只是提示，直接请求 API 同样按本表判定。

| 动作 | 所需成员权限 | 必要案件角色 | 附加条件 |
|---|---|---|---|
| 查看案件、材料、证据、任务、报告 | `view` | 已分配该案（任意角色） | 未分配返回 404 |
| 创建、提交报告 | `edit` | 无（角色需具备 `edit`） | 状态为草稿或已退回 |
| 退回、批准、作废报告 | `approve` | `owner` 或 `reviewer` | 退回必须填写原因 |
| 正式下载报告包 | `export` | 已分配该案 | 指定报告已批准且依据未变化 |
| 创建、分派任务、调整期限、取消 | `edit` | `owner` | — |
| 开始、提交任务 | `edit` | 无 | 必须是任务负责人，或具备 `owner` 角色 |
| 退回、完成任务 | `approve` | `owner` 或 `reviewer` | — |
| 调整案件分工 | `manage` | `owner` 或管理员 | 见成员管理接口 |

两个补充口径：

- **撤权立即生效**：成员权限在每次请求重新解析，已签发的会话不会保留旧权限；撤去 `approve` 但保留 `view` 的人仍可查看，不能复核。
- **环境令牌没有案件角色**：`LAW_REVIEW_API_TOKENS_JSON` 中的身份只有 `case_ids` 与 `permissions`，除管理员外不满足任何角色条件，因此不能复核报告或任务。本机模式（`local`）视为管理员，不能用于多人验收结论。

## 6. 报告签发：冻结、批准与交付

页面顺序固定为：**选模板 → 新建草稿 → 提交复核（冻结正文）→ 冻结预览 → 批准/退回 → 下载指定版本**。

1. 提交复核时，服务端把当前正文渲染成不可变版本：所选模板的区块与静态正文、案件摘要字段、材料目录、证据内容与来源、纳入的问答正文与顺序、全量资金流水（顺序、条数、币种）以及所选附件的文件名、大小与内容摘要。渲染器版本一并登记。
2. 两个摘要分开计算：`content_hash` 覆盖渲染出的文件与附件摘要，`source_hash` 覆盖案件/材料/证据/问答/流水/模板等输入。批准时间、批准人与最终 ZIP 摘要不进入自身摘要。
3. 批准只作用于复核人实际预览的冻结版本：批准前再次校验冻结文件、附件字节与来源摘要。并发批准/退回使用状态与 `row_version` 条件更新，只有一个成功，其余返回冲突。
4. 正式下载读取指定报告版本的冻结字节，不再从活动表拼接正文。清单 `清单.json` 登记报告 ID/版本、`content_hash`、`source_hash`、冻结版本号、批准记录、冻结文件摘要与包内实际文件摘要；期间作废、撤权或依据变化会拒绝登记并返回失败。
5. 以下情况要求重新准备并审批新版本：案件信息、材料正文/目录、证据、纳入的问答、资金流水、同一模板的区块或静态正文发生变化。未选择问答区块的报告不依赖聊天内容。
6. 冻结工件存放在数据目录 `report_versions/case-<案件>/report-<报告>-<序号>-<随机>/`，数据库只保存相对路径，随 `scripts/data_snapshot.py` 一并备份/恢复；恢复到新目录后仍可正常预览与下载。目录是受保护数据，不提供静态下载地址。
7. 历史上批准但没有冻结正文的报告保留批准人与事件，但不能正式导出：需要重新准备、冻结并批准。冻结中断或工件缺失时，预览、批准与下载都会明确失败，不会伪造成功。
8. 本批不自动清理历史工件。空间预算按每案「渲染文件总量 × 复核轮次」估算，超过保留期由运维按记录手工归档。

## 7. 人员变动流程

| 场景 | 操作 | 结果 |
|---|---|---|
| 新同事入职 | 管理员在“成员与权限”创建成员，一次性令牌当面交付 | 成员按案件分工获得权限 |
| 转岗/加案件 | 案件总览“案件分工”调整角色 | 下一次请求按新角色执行 |
| 离职/停用 | 停用成员 | 令牌与会话立即失效，历史审计与任务保留 |
| 令牌泄露 | 轮换令牌 | 旧令牌立即失效 |
| 复核人变更 | 新复核人批准新报告版本 | 旧批准版本置为已作废 |

## 8. 运行提醒与值班责任

当前版本提供 `/api/health`、`/api/ready`、结构化日志与 `security_events`，**没有内置告警通道**。下列值守项由律所指定运维负责人执行外部巡检（系统定时任务或人工），本版不声称这些监控已接入：

| 值守项 | 建议频率 | 失败处理 |
|---|---|---|
| `/api/ready`、`legal_verification=unavailable` | 每 5 分钟 | 法条语料缺失只降级核验；接口连续失败通知交付接收人并暂停签发 |
| 数据目录剩余空间 < 2 GiB | 每小时 | 停止批量导入、清理旧导出包、扩容后复核 |
| `python -m scripts.collaboration_acceptance --data-dir ... --multi-user` | 每日（只读，可随时执行） | 出现 `FAIL` 时按检查名定位；`multi_user` 失败说明身份模式退回单用户 |
| 备份任务与恢复演练 | 每日备份、每月演练一次 | 备份失败当日重试；演练失败保留目录并记录责任人 |
| 登录失败与 `security_events` 中 `denied` 增长 | 每日 | 核对来源与成员状态，必要时停用成员并轮换令牌 |
| 已批准报告“依据已变化”后长期未重新签发 | 每周 | 通知承办律师重新准备、冻结并复核 |

值班人、备份周期与保留位置在 U1 前登记到第 9 节放行参数；未登记时不能以本文默认值视为律所已接受。

## 9. 未覆盖项

- 没有在线热备、异地复制、自动故障转移与多实例部署承诺。
- 没有邮件/短信令牌投递，令牌由管理员手工转交。
- 没有外部身份平台停用事件的实时同步；离职需在本系统停用成员。
- 模型服务连通性检查仅在显式传入 `--probe-model` 时执行；`/models` 通过不代表推理效果通过。
- 恢复演练只覆盖数据与工件层，恢复实例的真实启动与业务链路属于 U1 人工验收。
- 未登记的目标硬件、人数、并发与容量阈值不能由开发机结果推定满足。
