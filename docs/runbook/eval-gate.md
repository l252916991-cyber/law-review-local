# 答案质量门禁

改动提示词、检索、路由、可答性判断或换模型之前，先跑门禁：在冻结的 v2 评测集（演示案件 60 题）上，本次结果不能比已登记的基线差。实现见 `app/eval_gate.py`，命令行入口为 `scripts/eval_gate.py`。

## 两种模式

| 模式 | 用途 | 规则 |
| --- | --- | --- |
| `rules` | CI 每次推送都跑；不调用模型，走真实的检索、路由、可答性和引用卡片路径 | 结果确定：任何一道原本通过的题失败即阻断；通过题数、正确拒答数、引用到全部必需页的题数都不许下降；禁止断言不许增加。推理配置与基线相同而结果不同时，按“不确定性”阻断 |
| `model` | 本机接真实模型时跑 | 采样有噪声：通过题数最多允许比基线少 2 题、正确拒答最多少 1 题；禁止断言不许增加；基线 p95 时延 ≥ 200 ms 时，本次 p95 不得超过基线的 1.25 倍 |

阈值写在 `THRESHOLDS`，属于预先登记的口径，改动它需要单独提交并说明理由。模式或评测集与基线不一致时直接报配置错误（退出码 2），不做比较。

## 命令

```sh
# 与已登记基线比较；通过退出 0，被拦下退出 1
uv run --locked python scripts/eval_gate.py --report output/eval-gate.json

# 本机真实模型（端点必须是回环地址）
uv run --locked python scripts/eval_gate.py --mode model \
  --endpoint http://127.0.0.1:8000/v1 --model ACTUAL_MODEL_ID

# 有意改动并确认结果后登记新基线；原因与上一版摘要写进 history
uv run --locked python scripts/eval_gate.py --update-baseline --reason "说明改了什么、为什么可以接受"
```

模型模式的基线已登记：本机 Qwen3.8-27B 4-bit，首轮 51/60，按失败题修复后第二轮 57/60（2026-11-02，[两轮记录与复核](../history/eval-gate-model-baseline-20261102.md)）；评分升为 v4 后，改用第三次运行（a71abd4）的回答重新评分登记，60/60。要和它比较，端点、模型名、`LAW_REVIEW_LLM_TEMPERATURE=0.2`、`LAW_REVIEW_LLM_MAX_TOKENS=700` 需与登记时一致，否则比较的是另一套推理配置。如果没有任何一题实际调用到模型（端点不通、模型名错误），门禁报配置错误，不会把规则回答当成模型结果。单题模型调用失败记为该题失败，不跳过。

模型模式一轮要二十多分钟。已经跑完并复核过的报告可以直接登记，不必重跑：

```sh
uv run --locked python scripts/eval_gate.py --update-baseline --from-report output/.../report.json --reason "..."
```

门禁会用当前代码重新算推理清单：门禁版本、提示词、推理模块摘要、评测集、数据库后端任何一项与报告不同都拒绝登记，并列出不同的项；模型名、端点与采样参数取自报告。基线里记下报告文件的 SHA-256。

没有基线时，摘要标题写“未比较（没有基线）”，退出码 2；不会写“通过”。

## 评测其他模型

门禁的分数只能和**同一个模型**的基线比。评分按基线模型的写法校准，换模型后分数的差距里混着格式、评分口径和真实质量（[跨模型记录](../history/eval-gate-cross-model-20261107.md)：35B-A3B 两次运行的 18 道失败题里没有一道是回答本身错了）。所以给其他模型单独指定基线文件：

```sh
uv run --locked python scripts/eval_gate.py --mode model --endpoint http://127.0.0.1:8000/v1 \
  --model OTHER_MODEL_ID --baseline benchmarks/eval_gate/baseline-model-OTHER.json --report output/other.json
```

第一次没有这个基线，只出报告（退出码 2）；逐题复核后，再用 `--update-baseline --from-report` 登记为该模型自己的基线。

## 回放：不接模型，检验模型调用之后的改动

改回答契约、引用处理、可答性或评分时，可以用保存的真实模型输出检验，不需要跑模型的机器：

```sh
uv run --locked python scripts/replay_model_gate.py output/eval-gate-models-.../MODEL_DIR --report output/replay.json
```

脚本在本地起一个假端点，按问题返回该次运行保存在 `model-calls.jsonl` 里的原始输出，然后在当前代码上跑一遍模型模式。记录里必须是模型返回的原文：维护者本机的采集脚本从 2026-11-07 起在来源标记改写之前取文本（改写后的文本另存为 `rewritten_answer`）；此前用带改写的代码采集的两次运行（35B 第二次、27B 第三次）存的是改写之后的文本，只能用来检验改写之后的代码。先用运行时的代码回放，结果必须与原报告逐题一致，回放才可信；再用改动后的代码回放，看哪些题变了。如果改动影响了送给模型的问题或检索结果，找不到对应输出的调用会被列出（退出码 1），这时只能重新跑模型。回放报告里的时延不是模型时延。

## 报告里有什么

- **推理版本**：`inference_id` 由提示词版本、系统提示摘要、可答性与上下文策略版本、检索与回答相关模块的文件摘要、数据库后端、模型设置共同决定。同一个 `inference_id` 一定对应同一套推理配置。
- **指标**：通过题数、引用到全部必需页的题数、正确拒答数、禁止断言数、p50/p95 时延。评分规则见下一节，不调用模型。
- **回答**：每题的回答、引用、状态与时延（评测集是虚构案件），评分口径以后变了可以据此重新评分。
- **替律师下结论的回答（只报告）**：模型回答里以自己口吻判定主观状态、否定一方说法、作法律定性的句子，逐题列出供复核，不参与阻断。规则与校准见[检测校准记录](../benchmarks/overreach-detector-20261102.md)。
- **逐题变化**：原本通过、现在失败的题号（阻断原因），以及原本失败、现在通过的题号（确认后可登记新基线）。

CI 把 Markdown 摘要写进 GitHub Actions 的 Job Summary，完整 JSON 随测试证据上传。

## 评分口径

| 门禁版本 | 评分函数 | 与上一版的区别 |
| --- | --- | --- |
| `eval-gate-v1` | `score_answer_v2` | — |
| `eval-gate-v2` | `score_answer_v3` | 拒答措辞增加“未记载”“没有记载”“不包含”“拒绝执行”“无法执行”；禁止断言出现在否定词后的引号里（“不会回复‘删除已完成’”）不计。必需要点、必需页与引用规则不变 |
| `eval-gate-v3`（当前） | `score_answer_v4` | 日期统一格式（“2024年11月8日”等于“2024-11-08”）；要点词里的“没有”可写作“未/没”，“只”可写作“仅”；结论段里“无法/不能/不会/不予……提供/列出/推导/伪造……”或“未执行”算拒答；同一句有“要求/指令”和拒绝词时，引号里的禁止短语算转述。必需页与引用规则不变 |

不同评分口径的基线与运行结果不能比较，门禁直接报配置错误。改口径之后要重新登记基线：规则模式直接重跑；模型模式不必重跑模型，用保存的回答重新评分即可（`--from-report`，旧报告没有保存回答时再加 `--answers` 指定运行时记录的回答）。重新评分前，门禁先用原口径把这些回答再评一遍，必须与原报告逐题一致，否则拒绝，以免把别的回答当成这一轮的。

v3 的新增措辞是看了两轮模型回答之后选的，这两轮对 v3 来说是样本内数据，对照与局限见[模型门禁两轮记录](../history/eval-gate-model-baseline-20261102.md)。`score_answer_v2` 保持不变，三组对照实验等已发布的 v2 结果仍可复算。

v4 的规则在实现之前单独提交，同时附上 6 次已保存运行的人工复核标签；v3 在这些运行上的误判失败率是 50%，v4 是 5%（样本内）。规则、两处实现时的修订和逐题对照见[评分 v4 记录](../benchmarks/answer-scoring-v4-20261108.md)。v4 仍然查不出说话人张冠李戴，也不核对必需要点以外的每一句话。

## 边界

v2 评测集由编码助手在单一虚构案件上构造，未经律师标注（见[答案级评测手册](answer-evaluation.md)）。门禁回答的是“这次改动有没有让已有的题变差”，不是法律准确率；规则模式通过不代表模型回答正确。
