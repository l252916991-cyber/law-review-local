# 3-8 LoRA 第二轮（round-2）结果：管线修复后仍为负收益

日期：2026-09-14。结论：**未通过验收，不接入**。本轮与 round-1 的关键差别是**管线已修好**——
因此负收益不能再归因于实现缺陷，而是**训练数据风格与评测参考的分布冲突**。计划见
`3-8-sft-round1-plan.md`，管线缺陷审计见 `3-8-sft-truncation-audit.md`。

## 本轮修复（相对 round-1）

1. **答案掩码**：`TextDataset.process` 返回 `offset = len(encode(prompt))`，loss 只覆盖答案
   与结束符。逐 token 自检通过（`train_text_masked.py --selfcheck`），实测监督 token 144/步
   （round-1 为整条 ~430）。启动器 `output/sft-38-v2/train_text_masked.py`。
2. **完整样本冻结**：按训练 tokenizer 筛 `prompt+answer+eos ≤ 512`，train 2,586 / valid 165 /
   holdout 168；无截断、答案非空、结束符完整（round-1 的 403 条截断样本全部剔除）；
   被截样本 pad 区误入 mask 的问题随之消失。
3. **内存护栏**：启动前清空 oMLX、训练期 90s 守护线程卸载闯入模型。训练 2,586 步全程
   **零守卫拦截、零冻结**；上一轮导致卡死的"训练 13.9GB + oMLX 9.15GB 并发超卖"不再复现。

## 训练（从 checkpoint 400 续跑，全程无损）

val loss 由 1.61 降至 **1.462@2400（最低点）**，选该 checkpoint。曲线单调下降无明显过拟合
平台，符合完整 1 epoch 的预期。

## 根因：数据风格 vs 参考分布

管线修复后，退化机制收窄为单一来源：**DISC Pair-QA 的训练分布本身**。
- 训练答案是**短篇自由散文**（p50 263 字，52% 带引用且多为概述式）；
- 3-8 参考是**两段式**（`回答:…法律依据:…`）+ **具体条文号**，中位 680 字。

模型忠实学到了训练分布，于是剥离评测要的骨架、丢引用、答得更短——ROUGE-L 直接下跌。
1-2 的 90→10 是同一机制在判别任务上的极端表现（该任务 out-of-distribution，模型仍套用
3-8 的论述格式）。**"有法条引用"的比例（52%）远不等于"引用适用且结构对齐参考"**——这是
`3-8-sft-data-audit.md` 里"引用率只作分层、不作筛选"那条边的直接印证。

## 三轮 SFT 的合并结论

| 轮次 | 数据 | 管线 | 3-8 配对 | 跨任务 |
|---|---|---:|---:|---|
| 2-2 | 同质合成标注 | 正确 | — | 全量 −16.2pp |
| 3-8 r1 | DISC 真实（含截断/未掩码） | **有缺陷** | dev20 −2.79pp | 1-2 −30pp |
| 3-8 r2 | DISC 真实（管线已修） | **正确** | 全量 −3.01pp | 1-2 −80pp |

**管线已排除，问题在数据**：公开咨询语料与 LawBench 参考的**答案组织规范**（两段式 + 条文
引用 + 详尽度）不一致，直接监督反而把模型拉离目标分布。要再试，前置条件是**目标风格对齐的
数据**（如按参考范式改写/合成的咨询题，但 2-2 证明同质合成又会坍塌），或**换基座**——而不是
继续在这份数据上调参。建议 SFT 线暂时归档，转向提示与检索层。
