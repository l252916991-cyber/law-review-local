# 法条库重建与 1000 题配对实验计划书

日期：2026-10-24。背景：2026-09-14 的 63.32% 依赖 canonical 85 部法条库（1-1 条文替换、3-2 词法 RAG），该库与所有 `legal_corpus*` 目录在本机已丢失；当前万题（4-bit、无法条库）只能产出「无检索」基线。本计划恢复可复现的语料，并用同一模型做有/无库配对，作为是否引入 27B 的决策依据。

执行状态更新（2026-10-24 18:15）：P1 部分完成——`build_legal_corpus.py` 抓到 **32/49** 份官方法规，17 份来源链接失效或改版；1-1 覆盖 **220/500**（缺 35 部法、280 题）。P2 被官方接口变更阻断：国家法律法规数据库的 `/reader/text` 现在只返回版式字段（`id/index/width/height/cropbox/areas`），不含正文，逐法抽取均报 `missing=[1..N]`；搜索、详情、预览与页数接口仍正常。因此 **canonical 85 部法条库当前无法完整恢复**，需适配新版 reader（可能转页面图像 + OCR）或为缺失 35 部法逐部另找官方发布页。P4 可在 220/500 覆盖下先行，用于测传导系数，但不能声称已达到 63.32% 的语料口径。

## 1. 目标与边界

| 目标 | 说明 | 不在范围 |
| --- | --- | --- |
| 恢复冻结语料 | 官方来源、版本截止 2023-11-13、保留 URL/哈希/版本证据 | 不以 benchmark 参考答案构造查询或语料 |
| 量化语料增益 | 同模型、同题、同评分器，有库 vs 无库配对 | 不改评分器、不调提示词以迁就结果 |
| 27B 决策门 | 用 1000 题分层的配对结果判断是否值得跑全量 | 不在无配对证据时直接烧 20 小时万题 |
| 既有运行 | 不干扰进行中的 9B 4-bit 万题 | 不切换生产配置、不改用户全局设置 |

## 2. 执行步骤与退出条件

| 步骤 | 工作 | 退出条件 |
| --- | --- | --- |
| P1 基础语料 | `scripts/build_legal_corpus.py --output output/score85/legal_corpus`（58 份官方法规正文，逐份抓取官方页面，保存原始 HTML 与解析结果） | 构建无失败项；`--verify` 通过；`valid=true` |
| P2 覆盖测量与补充 | 用进行中的万题 1-1 结果跑 `scripts/lawbench_coverage.py` 得未覆盖清单（`--worklist`），再以 `scripts/build_npc_corpus.py --cutoff 2023-11-13` 从国家法律法规数据库补齐 | 1-1 条号覆盖 **500/500**；补充集 `--verify` 通过 |
| P3 canonical 合并 | `scripts/build_canonical_corpus.py --root output/score85 --output output/score85/legal_corpus_canonical_v2`，同一 `(law_name, version_date)` 只保留一份原文，冲突即拒绝 | 合并报告无冲突；语料文档数、逐文书 SHA-256 与经济性摘要冻结 |
| P4 1000 题配对 | 同 `Qwythos-9B-v2-OptiQ-4bit`、`lawbench-task-guided-v4`、`lawbench-local-v3`、`seed=42`、每类 50 题；两臂：无库 / 有库，逐题配对 | 两臂各 1000 题完成、0 技术失败；报 1-1、3-2 与混合均分的配对差值和 95% 区间 |
| P5 27B 决策门 | 若 P4 有库臂稳定（1-1 明显提升、其余任务无回退），再以同一 1000 题跑 27B 4-bit 一臂 | 给出「是否值得上全量」的结论与成本估算；无结论则不跑万题 |

## 3. 口径与约束

1. **语料只来自官方发布**：全国人大/国务院/部委/地方政府官网或国家法律法规数据库；保留原始字节、URL、抓取时间、版本日期与版本证据，禁止把 LawBench 答案或旧回答写入语料。
2. **版本冻结**：benchmark 口径固定 `cutoff=2023-11-13`（LawBench 固定提交日），生产口径必须另用 `--source-as-of`，两者不混用。
3. **配对定义**：两臂必须同题同提示同评分器，只允许语料这一个变量；`1-1` 的官方条文替换与 `3-2` 的词法 RAG 均由 `--corpus-dir` 触发，因此有库臂需确认 `routing.task_3_2.enabled=true`。
4. **结果解读**：混合均分是 20 类等权平均，不是准确率；1-1 与 3-2 的变化主要反映检索/替换，不代表模型法律能力整体提升。
5. **资源**：语料抓取只占网络与磁盘，不占用模型服务；配对实验等万题结束后串行执行，避免并发争用导致时延与用量失真。
6. **27B 前置**：权重需下载并冻结 SHA-256；safe 守卫上限约 17.2GB，27B 4-bit 权重接近顶格，必须记录实际加载与是否 507；跑全量前先用 1000 题配对。

## 4. 证据与交付

- 语料：`output/score85/legal_corpus*`（Git 忽略，含 manifest、原始页面、逐文书哈希），合并报告单独保存。
- 配对：两臂各自独立的运行目录（`manifest.json` 记录语料目录与文件指纹），逐题 `detailed_results.jsonl`，配对差值脚本结果另存。
- 结论写入 `docs/benchmarks/` 下的实测记录，并在 README 的评测分层处登记；未通过或未执行的步骤如实标注，不用「已提升」措辞包装。

## 5. 风险与回退

| 风险 | 处置 |
| --- | --- |
| 官方页面改版/404 | 记录失败来源与替代来源，保留原始失败；不静默替换为二手转载 |
| 覆盖率不足 500/500 | 用 worklist 迭代补充；仍不足则如实报告覆盖率与缺失条号，不声称已覆盖 |
| 合并冲突（同一法律不同版本正文不一致） | 按现有 `build_canonical_corpus` 规则拒绝并人工核对，不静默取舍 |
| 27B 内存不足或 507 | 记录实际失败，退回 9B 4-bit 有库臂结论；不为加载 27B 降级守卫或关停其他用户进程以外的手段 |
| 与万题并发争用 | 配对实验排队到万题结束；如必须并行，另行登记并分开解释时延 |
