# 3-8 LoRA 首轮退化审计：训练管线缺陷确认

日期：2026-09-13。结论：**上轮退化有三个管线级原因，均有代码与数据证据；"模型能力不足"的
归因不成立，重训有具体可修项**。本轮只审计，未开新训练。审计对象 = round-1 实际使用的
mlx_lm 0.31.3 数据管线 + `output/sft-38-v1/dataset/train.jsonl`（3,000 条）。

## 发现一：loss 未屏蔽 prompt，55.3% 的梯度在教模型复述输入

`mlx_lm/tuner/datasets.py` 的 `TextDataset.process` 返回 `(tokens, 0)`——text 格式**固定
offset=0，系统提示、任务说明与题面全部计入 loss**。实测 round-1 训练集中 prompt token
占比 **55.3%**：模型的一半以上训练信号来自"复述提示与题面"，而非"生成回答"。

对应退化证据：on 臂复读循环题（3-8_0363）循环输出的"小孩户口上在男方家"正是**题面短语**；
1-2 判别任务的 30pp 退化也与"强化复述输入"相容（多选题的题面/选项被当作可生成内容）。

## 发现二：13.5% 样本被硬截断，截断点 100% 落在答案段，停止符几乎全部丢失

`trainer.py` 按 `batch[j][:512]` 硬切。实测：

| 指标 | 值 |
|---|---|
| 超 512 token 样本 | **406 / 3,000（13.5%）**（总长 p50 379、p90 536、max 8,165） |
| 截断点落在答案段 | **406 / 406** |
| 被截样本答案可见比例 | 中位 83%；**29 条可见不足一半**；完整存活仅 4/406 |
| 结束符 `<\|im_end\|>` 存活 | 402 / 406 被截样本丢失 |

对应退化证据：被截样本教会模型"长序列无终止"；on 臂 3 题 length 截断、答案长度 821→308、
引用率 20/20→12/20（**引用段恰在答案后半，是截断的首当其冲者**）。

## 发现三：prompt/completion 格式的掩码不可用（2-2 结论复核成立）

`CompletionsDataset` 的 prompt/completion 格式会把字段重新套 `apply_chat_template`
（messages=[user, assistant]），且 `mask_prompt` 的 offset 以 `add_generation_prompt=True`
渲染——Qwen3 模板默认 kwargs 产生开口 `<think>`，与评测路径的闭合 think 错位。2-2 记忆
的"二次套模板"结论复核成立，因此**不能靠换数据格式修复掩码**。

## 修复路径（供重训决策，本轮未执行）

1. **掩码**：保留 text 预渲染（评测逐字节对齐），训练侧以包装器替换 `TextDataset.process`
   返回 `(tokens, prompt_token_len)`（与 `serve_adapter.py` 同类的 monkeypatch，训练 venv 内
   运行），使 loss 只计答案与结束符。唯一同时满足"渲染对齐 + 目标正确"的路径。
2. **截断**：以完整样本为筛选前提——保留总长 ≤512 的样本（或新内存窗口下重定 seq），
   答案被截的 406 条不进训练；与"小而精"的数据精筛（引用适用、事实分析明确）合并执行。
3. **训练量**：在上述修复后补足完整 epoch（2-2 背诵有效性在 ~3.75 epoch；本轮 0.68 epoch
   的"背诵测试不适用"结论随管线修复重新评估）。

三条均不涉及提示或检索改动；模型基座是否更换（路线 3）建议在管线修复的重训结果之后判断。
