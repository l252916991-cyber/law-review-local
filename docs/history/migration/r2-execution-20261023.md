## 3. 审批、预算与未知事实

审批按节点集合保存，绑定规范化动作、参数、资源/策略版本、主体、审批人和期限。多个待审批项互不覆盖，消费一项不能放行另一项。消费与准入同事务；消费后、journal 开始前重启，可保留原准入而不重复消费，同时重新核验期限和权限。

模型/工具调用先预留节点最大 Usage，完成后按实际结算；物理工具尝试及嵌套用量进入共享 journal，重启不重置计数，结果复用不重复扣费。恰好达到限额可完成，超额保留实际消耗并失败；未知效果的已知超额也会阻止后续花费。零 token 纯工具和零嵌套步数均保持精确额度。

已发送模型但响应未持久化，或工具已开始但效果/费用无法证明时，保留 `unknown`、实际已知用量及预留，返回 `needs_reconciliation`。R2 采取保守对账策略，包含幂等/只读调用的未知嵌套费用；不会因安全重放效果而抹去费用。配置的可信宿主 resolver 只能查询既有回执/响应或使用明确证据，返回完整输出、总实际用量与证据引用；没有证据则继续待对账。

UTC 开始时间、deadline 和时钟高水位持久保存；等待审批计入墙钟，重启不续期，时钟倒退拒绝推进。取消接受与执行终止分别记录，已完成回执保留，未知效果优先对账。flock 不允许接管仍存活的 owner；不提供分布式租约或并行吞吐保证。

终态、checkpoint 和 outbox 原子提交，发布在提交之后。事件以 run/revision ID 去重，承诺至少一次投递；发布后确认前退出可重复发布同一 ID，不生成未提交成功。授权历史读取与删除覆盖 R2 图、outbox、审批和 journal，外部回执及保留政策由宿主负责。
