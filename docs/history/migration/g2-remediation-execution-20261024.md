# G2 相关性修复实施记录

日期：2026-10-24（北京时间）。依据：[修复计划](g2-remediation-plan-20261024.md)。执行起点 `bc2a715`，工作区干净；实施分支 `codex/g2-answerability`。仅使用合成材料、现有本机 Qwythos 9B 与检索模型，不外发、不付费。DevSpace 打开工作区仍返回内部错误，继续使用本地工具。

## 1. 根因与复现

保留 D06 的原五题、旧报告和数据库。原无关查询没有 keyword 候选，却有六个 dense 命中且被标记为 high confidence；重排仅用于排序。模型在回答开头已说明问题与本案无关，仍继续输出本案结论；原 Critic 格式校验与来源原文校验均通过。检索命中数量/来源多样性、原文真实及规范引用，均未验证回答是否针对原问题。

原生成输入还将专家摘要拼到问题末尾，要求只给律师最终结论，使问题与案件概括混在同一指令中。修复候选单独传入原问题与资料，保留原专家图，但不让专家摘要替代问题。没有为原负例写关键词特例，也没有按少量题目猜测 rerank 阈值。

原故障摘要在私有 `output/migration/g2-remediation-20261024/reproduction/original-failure.json`；历史 D06 证据继续保留。

## 2. 候选契约与持久化

新增 `app/review/answerability.py`：最终协议 `candidate-answerability-v8` 只接收 decision、reason、findings 三个字段；decision 区分 supported、unrelated、insufficient。每项 finding 给出文本与非空来源编号数组，支持同义改写和按现有资料限定范围的宽泛阅卷。具体事实缺少支持时拒绝，拒绝的 findings 必须为空，不能附带其他主题的法律结论。JSON 重复键、非法结构、缺少/越界来源、伪造文本内引用和混合拒绝/成功发现均为系统校验失败，不计正确拒绝。

材料明确记载“未见某记录”时，可以据此回答该快照内记录有无，仍不能推断事情没有发生。v6/v7 的租赁凭据问题曾被误拒，v8 保留明确的范围区别并恢复较完整的协议提示；最终设备保修样本仍有一项同类误拒，见第 4 节。询问具体批准人而没有相应记录时仍按材料不足处理。

宿主校验每项来源编号后生成引用并补充固定律师复核提示，随后仍校验引用格式、真实来源及精确原文。模型不再同时排版自由文本引用和重复声明另一份索引，模型宣称无需复核仍被拒绝。宿主独立执行严格结构校验；不依赖服务端语法约束。该边界是来源校验加模型自报可回答性，不是完整语义蕴含证明；`semantic_entailment_checked=false` 保留。

候选图升级为 `legal-review-candidate-v2`、宿主适配版本 v2，绑定策略版本、提示词 SHA 和策略实现文件 SHA。旧候选图/策略不被新版本静默重解释；已有运行不自动转新模型或重跑。候选 v2 明确要求实际 model 节点，拒绝 rule-only 请求；旧隔离规则图与正式入口未更改。

候选直接校验结构化响应，不使用旧 `strip_reasoning` 的中文规划词启发式。实测发现该启发式会把 reason 中正常出现的“问题要求”删空；原生对照仍沿用原逻辑，保留其差异。截断及非法 provider 响应仍按实际已知用量处理，不降级为规则成功。

业务拒绝以失败 finish 步骤、`answerability_rejected` 诊断及明确决定同事务持久保存；召回候选仍可审计。没有成功消息、记忆草稿或 final_answer，恢复不重发已知调用、不重复效果。服务失败、无效协议和 unknown 不冒充业务拒绝；未知预留仍由原账本处理。

## 3. 对照与工程验证

比较报告升级为 schema v2，分别记录候选业务结果、原生基线误接受、工程一致性和测量有效性。正确拒绝检查绑定已核验的失败回执与实际已知模型响应，不再要求召回 contexts 为空。原生基线接受负例时如实记录，双方同错不会让候选正确性通过；非法后端响应也不能借规则 fallback 隐藏。

原生提示词和五个关键算法文件固定到 `ab779cb` 字节身份，运行前检查，漂移即拒绝开始对照。该身份范围是原生算法和提示词；后端治理与源快照采用当前候选。共享检索/记忆与各自检索仍分别报告；没有声称两个不同提示词的回答应完全相同。

新增回归覆盖三类决定、非法/重复 JSON、来源与引用、宿主复核提示及模型否认复核、业务拒绝无成功效果、策略变化拒绝旧运行、禁止 rule-only 绕过、系统失败不算正确负例和原生基线漂移拒绝。原 dense 错误成功用例保留原输入并变为正确拒绝断言。实际 SIGKILL 测试扩展到拒绝结果，在受理、派发、响应与 journal 窗口验证新进程恢复；派发未知不重发。

## 4. 本机实际模型复验

保留各轮失败：早期结构化回答出现数字引用、遗漏复核提示、重复声明来源索引与实际答案不一致，以及旧思考过滤误删正常 reason。后续 v3 轮 13 题中 12 题通过，租赁宽泛题被模型判为可回答却漏排引用标记，仍被系统正确拦截；由此将引用排版移到宿主，来源编号校验仍保留。中止批次的 unknown 留在原验收库内，不通过恢复重发；新试验排他新建验收库和部署身份，使用独立证据目录，不算旧调用已对账。
