# 三组对照实验协议（冻结版 v1）

- 日期：2026-10-27（Asia/Shanghai）。
- 对应计划：[agent-portfolio-plan-20261027.md](agent-portfolio-plan-20261027.md) 第 4、6、7 节；配套实现：[驱动](portfolio-p1-ablation-driver-20261027.md)、[保留集](portfolio-p2-holdout-20261027.md)、[分析层](portfolio-p2-analysis-20261027.md)、[可复现性修正](portfolio-determinism-20261027.md)。
- 用途：这是可入 Git 的**协议与数据清单**；数值结果单独在对照报告里，且只在真实批次存在后才写。协议一经用于真实批次即冻结，改动需新版本号。

## 1. 要回答的问题

1. 在同一模型、同一冻结来源和同一调用预算下，结构化交接（B）相对基础 RAG（A）是否改善回答？
2. 在 B 之上，来源核对与跨专家待补信息（C）带来什么增量？
3. 改善出现在哪些类别，付出多少输入 token 与耗时，哪些类别退步？
4. 失败、未尝试与未知用量的分布如何，能否解释为协议问题而不是模型能力？

## 2. 组别定义

| 组 | 模型输入 | 生成后处理 |
|---|---|---|
| A 基础 RAG | 系统提示 + 检索路由 + 原问题 + 冻结卷宗片段 | 无 |
| B 结构化交接 | A + 原始规则专家发现（`facts / evidence / contradiction / gap_detection`，剥离 `upstream_review`） | 无 |
| C 交叉审校 | B + `source_checks`、`issues`、跨专家待补项与限制声明 | 原始回答通过产品校验后追加确定性分歧附录 |

- 实现入口：`app/collaboration_ablation.py` 的 `group_note()`，`C = B + crosscheck` 前缀关系由回归锁定。
- 专家是确定性规则节点，协议禁止把 C 描述为“多个自主 LLM 分别推理”。

## 3. 不变项

同一冻结检索上下文、同一问题、同一模型、同一采样参数、同一次生成调用、同一引用契约（`validate_review_answer`）、同一案件授权、同一超时与总量限制、同一硬上限。禁止长期记忆读写、自主工具循环与模型回退；这些能力只在产品端到端流程另行验证，不进入对照因果结论。

## 4. 数据与身份

| 项 | 冻结值 |
|---|---|
| 开发集 | `benchmarks/answer_eval/v2/dataset.json`：60 题、14 页，`source_sha256=b912f4ca…`；类别 正常 30 / 矛盾 10 / 不足 8 / 无关 4 / 缺法条 4 / 注入 4 |
| 保留集 | `benchmarks/answer_eval/holdout-v1/dataset.json`：6 案例、24 题、24 页，`source_sha256=66265fdb…`；类别 正常 12 / 矛盾 6 / 不足 3 / 无关 2 / 缺法条 1 |
| 算法身份 | native 基线 `specialist-review-v3`；`agents.py` 等七个文件摘要由 `native_baseline_identity()` 校验 |
| 提示与策略 | `chat-system-v4-multiturn-untrusted-history`、`candidate-answerability-v11-detail`、`answer-judge-v2-frozen-sources` |
| 标注来源 | 二者均为编码助手依合成材料编制，**未经律师或独立人工标注** |
| 隔离库 | 开发集用演示种子；保留集由 `dataset.json` 的 `cases` 直接播种（`seed=False`），逐页比对冻结正文 |
| 引用可达 | 冻结上下文必须覆盖题目的全部可接受页；`prepare` 逐题记录 `citation_reachable`，为假时该题的通过率不作为质量证据 |

## 5. 预算与停止规则

| 项 | 值 |
|---|---|
| 预检 | 3 题（正常/不足/矛盾各一）× 3 组 = 9 次 |
| 开发集 | 60 题 × 3 组 × 1 轮 = 180 次 |
| 保留集 | 24 题 × 3 组 × 3 轮 = 216 次 |
| 合计 | 405 次生成，不含 Judge、重跑与演示 |
| 硬上限 | 单次提示 48,000 字符、输出 900 token；超限即失败，不截断、不改写配置 |
| 停止 | 预检不可用即停（批量调用 0 次）；出现契约/安全/数据完整性异常即停并保存证据；修复后用新批次身份重跑 |

费用与单价在没有登记前为**未知**；本地 token 不是账单，也不等于零成本。

## 6. 采样与轮换

- 采样参数取配置值（当前 `temperature=0.2`、`max_tokens=900`），驱动不发送 `seed`；后端未声明 seed 能力，因此不承诺跨设备逐字一致。
- 轮换：`rotation(groups, index, repeat)`，第 `i` 题第 `r` 轮从第 `(i+r) mod 3` 组开始，降低缓存与加载顺序偏差。
- 保留集重复 3 轮；开发集 1 轮用于定位问题，不做统计结论。

## 7. 评分

| 层 | 规则 |
|---|---|
| 通过判定 | 确定性规则（必需要点、无据断言、引用精度、该拒答时是否拒答）；**按模型原始回答**计分，附录另记 `final_score` |
| 附录 | 只允许在校验通过的原始回答后追加；`appendix_changed_verdict` 记录“附录会把不通过变成通过”的次数，不计为模型收益 |
| 不可答题 | 拒答正确与可答题误拒分别报告，不合并成单一总分 |
| Judge / 人工 | 与确定性分数分列；κ 需要 ≥20 个有效匹配标签，缺人工或 Judge 不可用时留空 |

## 8. 失败分类

| outcome | 含义 | 计入分母 |
|---|---|---|
| `ok` | 有模型回答且通过契约 | 是 |
| `contract_failed` | 回答未通过格式/来源/复核提醒校验，C 扣留附录 | 是 |
| `invalid_response` | 空正文或不可用输出 | 是 |
| `timeout` / `transport_error` | 传输层失败 | 是 |
| `model_unavailable` | 预检或调用判定模型不可用（规则降级在受控对照中的表现） | 是 |
| `budget_exceeded` | 超过登记上限，未发起调用 | 是 |
| `not_attempted` | 产品路径在生成前拒答（无冻结上下文） | 是（单列 `rule_refused`） |

未知用量写 `null` 并计 `unknown_usage`，从不写 0；任一失败都不自动重试。

## 9. 分析规则

- 按 `(题目, 轮次)` 配对；只在一侧的记录进 `unpaired`，不静默丢弃。
- 主报告给同题差值、分类结果、样本数、轮次翻转，**不预设“必须提升 X%”**。
- 区间按案例重采样（固定 seed），并注明只有 6 个保留案例，不能当总体估计或 SLA。
- 同案多题、重复轮次不作为独立案件；p95 等小样本分位数不作为 SLA。

## 10. 盲审规则（启用条件，实现见[盲审包](portfolio-p2-blind-package-20261027.md)）

- 从保留集按类别分层抽取至少 20 题；三组答案隐藏组别、随机顺序呈现。
- 每题绑定题目、答案与独立来源的摘要；重复轮次的取样方式预先登记。
- 开发者不得替独立审核人填写标签；缺人工即保持未完成。

## 11. 不得作出的声明

- 不把结构检查率、来源一致率写成法律准确率；
- 不把规则专家写成多个自主 LLM；
- 不把本机测试写成线上 SLA 或律所上线；
- 不在真实批次缺失时填写任何质量、token 或时延数字；
- 不把保留集结果当作跨案件泛化的证明。

## 12. 变更控制

- 协议改动或驱动改动 → 新批次身份；旧批次与旧报告保留，不覆盖。
- 保留集一旦用于调参即转为开发数据，需另建 `holdout-v2`。
- 受摘要门禁保护的算法文件改动必须显式重登记基线，并说明对提示、检索与契约的影响（本次为 `specialist-review-v3`）。
