## 4. P01 必须明确的协议内容

以下为设计要求，字段名称和具体存储结构在 P01 冻结。

| 对象 | 必须表达的信息与规则 |
| --- | --- |
| 运行身份 | application/scope/owner/run 身份、请求与输入摘要、运行模式、框架与编排版本；相同 run 不得换主体或参数冒充恢复 |
| 编排定义 | 稳定节点 ID、分支实例/迭代身份、依赖、输入摘要、完成输出及证据引用；只支持显式可重建的编排，不保存任意 Python 协程栈 |
| 调用身份 | 逻辑调用、物理尝试、幂等键、工具版本与效果类型、参数摘要、调用日志状态、可查询回执；节点状态必须可与已有 journal 对账 |
| 模型请求 | 稳定请求身份、模型/配置与输入摘要、响应及证据、已知/未知用量；明确已发送但响应未保存时可否重发，不能因没有工具副作用就忽略重复费用和不同输出 |
| 审批 | 精确动作/参数、资源版本、执行身份、审批人、有效期、策略版本、一次性消费与取消；多个并行待审批采用集合或确定性队列，不能覆盖旧项；恢复时重新核验授权 |
| 预算 | 累计已用、预留、未结算与未知用量、实际尝试次数、恢复后的剩余额度；模型/工具/重试/嵌套调用的归属不得重复收费 |
| 时间 | 持久开始时间、deadline 和审批有效期；明确等待审批是否计入墙钟及系统时钟变化的处理，不能跨进程复用 monotonic 数值，重启不能重置已用时长或延长承诺 |
| 所有权与并发 | 本机共享状态目录内的单运行所有者、修订号、占用/释放及崩溃接管条件；失效所有者不能提交新状态或继续准入；不扩展为跨主机保证 |
| 结果与事件 | 节点完成、运行终态、结果摘要、trace/checkpoint 关联及顺序/去重规则；明确终态提交与事件发布的先后及补发/重建，终态不能倒退；SDK 事件与宿主事件 v2 分别声明，宿主修订摘要不是递增游标 |
| 数据生命周期 | checkpoint/结果/trace 的授权读取、保留与清理边界；日志不含凭据，私有材料仅在授权私有状态中存放 |

需要区分“尚未执行”“已准入待执行”“正在执行或结果未知”“已完成”“待审批”“待对账”“失败/取消”等概念状态，不能仅凭缺少节点完成记录推定工具没有执行。具体状态名和迁移必须由事务边界及恢复规则支持。

优先复用现有 checkpoint、approval、invocation journal 和 ToolExecutor。按照[ADR 030](/Users/xiaoy/Documents/多agent协作/docs/adr/030-shared-tool-executor.md)，调用方负责持久化准入、审批和编排进度，共享执行器负责调用日志、尝试、重试、恢复判定及嵌套用量；不得分别计费或制造第二套审批账本。

现有审批消费与精确执行准入的原子保证应复用；P01 逐一列出节点状态、预算预留、审批消费、journal 和事件之间的事务边界。特别处理“审批已消费、执行准入已记录、journal 尚未开始”的状态，恢复时不能再次消费同一授权，也不能丢失已授权但尚未开始的动作。

## 5. P03/P04 的关键行为

1. **恢复采用新进程。** 测试从磁盘重建框架、上下文和编排，清空前一进程内存；不得以同一对象继续执行代替恢复证据。
2. **完整结果按身份复用。** 节点、输入和版本匹配时复用已持久完成结果；资料变化则按协议失效、拒绝或另建新运行，不能悄悄混用两版证据。
3. **未知效果先对账。** 写入已发生但未收到结果时，使用回执查询或明确的幂等契约处理。没有可证明结果的非幂等调用保留待对账，不能自动重试或改走旧运行时。
4. **审批精确且只消费一次。** 覆盖批准前后、消费前后、checkpoint 前后退出的窗口；过期、重复批准、撤权、改参或资源变化必须有确定行为。
5. **预算跨恢复连续。** 准入前持久化预留，完成后结算；重复结果不重复扣费，实际尝试不漏记。结果未知和用量未知保留显式状态，不能当零或直接释放全部额度。保留恰好达到限额允许完成、超过限额失败的既有边界。
6. **并行推进必须可重建。** 持久保存分支身份、依赖与完成集合，定义一分支失败/待审批/待对账时其他分支及 join 的行为；重复完成和重复 join 不能生成多个终态。先保证正确性，性能提升另行测量。
7. **所有权不能冒充外部回滚。** 接管后旧执行者必须失去后续准入和状态写入权；已经发出的外部调用仍须按效果类型处理未知结果，租约或进程锁不能证明它没有发生。
8. **取消和超时保留事实。** 阻止后续准入，按能力清理进程与资源；已提交的副作用保留回执，进行中的未知调用保留待对账。对“取消请求已接受”与“执行已终止”分别记录。

写工具和审批能力只向完成持久准入与恢复契约的自定义编排开放。既有一次性编排继续明确声明其边界，不能仅删除当前拒绝分支就宣称支持 R2；资格报告只对已完成验证的能力放行。
