## 4. 实施约束与关键设计

### 4.1 共享执行器保持单一状态来源

优先检查框架现有 `runtime/loop.py`、`sdk/kernel.py`、`state/invocation_journal.py`、`state/approval.py` 和 `runtime/budget.py`。新公共模块的名称和边界由 N01 决定，不按文档名称机械新建重复实现。

- 一次逻辑调用采用稳定标识，物理重试共享业务幂等键但分别计入尝试与用量。
- 参数/当前权限/策略/审批资格在副作用发生前检查；审批消费、调用记录、工具结果与 checkpoint 的顺序必须文档化。
- 已完成结果按现有契约复用；结果未知的非幂等动作进入对账，不自动重放。
- 保留当前 ReAct 已有写工具与恢复行为；kernel 在 R2 验收前继续限制自定义写入、审批和恢复。
- 执行器、kernel、外层流程明确事件和预算归属，防止重复计数、漏记失败和虚假完成。
- N03 的框架层故障验证可使用契约替身；真实宿主业务写入、job/会话闭环属于 E12–E16，不能作为本批已通过结果。

### 4.2 来源与规模兼容保持可验证

案件来源绑定 document_id、原始页码和正文摘要；法条来源绑定语料版本、文档/条款身份与文本摘要。纯法条结果应使用其真实法条来源，不伪造案件页来满足旧校验器。若结果/事件字段语义变化，按现有契约规则升版并提供历史适配。

继续使用既有工程限制：默认 500 页/200 万字符、显式上限 2000 页/2000 万字符、单页 20000 字符、命中页包 100 页/20 万字符。以上为当前工程边界，不等于已承诺生产容量。测试限值前、等于限值、超过限值；按实际支持范围明确拒绝或分批，不要求本批自动实现无上限分页。

资料发生变化、权限撤回、法条语料失效时必须失败关闭。引用原文可定位与结论语义正确分开评价，后者继续由 E17 专业评审负责。

### 4.3 模型治理复用已有核心

框架已有共享模型调用核心 `invoke_model_once`，本批重点是接入律所领域调用并完成工具执行共用，不重新实现同一核心。模型请求由框架受控路径驱动；模型配置、凭据和后端访问属于受信部署配置，不能由请求载荷提供任意 URL、路径或凭据。

LLM、embedding 和 reranker 分别记录逻辑调用 ID、实际后端/版本、开始结束、失败原因、重试、可获得的实际用量和预算结算。取不到真实用量标未知，离线假后端数据标测试值。框架已经计入的调用不能被宿主再次累计。

超时应区分单次调用与整次运行；不得把 soft deadline 描述成已经取消外部副作用。已有 reranker 失败是否允许降级，以当前业务规则和端口契约为依据，不能把“不中途降级”直接当缺陷修复。任何检索后端切换都显式记录，避免框架变化与模型/检索策略变化混在同一实验中。

正式旧 HTTP/UI 入口仍按 E14 排期接线。N06 关闭的是新适配链路中声明范围内的旁路；已准备但尚未接线的旧入口继续在 E01 登记，不能把接口准备完成写成全产品治理完成。

### 4.4 候选与安装规则

N03 若需要供 N06 使用，构建独立、可区分身份的工程候选，记录源码、SDK/协议、依赖锁、wheel 摘要、支持与拒绝的能力及适用验证。开发验证使用独立环境与明确候选配置，不修改框架安装目录，不用开发机绝对源码路径代替发行物。

现有 0.6.0 绑定继续作为既有基线，不原地覆盖。N03 的候选资格不等于 E11 最终发行资格；实现 R2 或更改公共契约后需要重新冻结、复验。电商部署的框架升级属于 E21/E22，本批只做必要的兼容回归，不改变其线上/本地运行实例。
