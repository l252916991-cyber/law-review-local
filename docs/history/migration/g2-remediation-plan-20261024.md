## 2. 调查依据与设计要求

当前代码中，`app/rag.py::vector_search` 的 dense 召回允许正余弦候选，neural rerank 参与排序；`app/agents.py::validate_review_answer` 检查格式、引用范围、来源存在和复核提示；`app/domain_writes.py::verify_sources` 核验来源身份与原文。上述机制分别有其职责，仍需调查无关材料为何进入回答以及最终接受路径为何未拒绝。不能仅凭代码形态判定完整根因，不能直接猜一个分数阈值。

`app/model_comparison.py` 目前把 `source_rejection` 与候选失败、检索 contexts 为空等条件绑定。新拒绝契约须覆盖“召回了材料，但材料与问题不相关”的场景；候选材料可以保留供审计。服务异常、超时、未知用量和业务拒绝必须具有可区分的结果，不能将任意失败计为正确拒绝。

设计时分别处理：问题与来源的相关性、材料是否足以回答、最终答案的来源支持范围。明确证据不足或无法判定时的响应与状态；保持现有原文校验。若采用额外模型判断，必须接入已有准入、预算、用量与恢复机制，并给出验证范围。没有相应证据时，继续保留 `semantic_entailment_checked=false` 的诚实声明。

## 4. 回归与比较设计

### 4.1 必须覆盖的场景

| 场景 | 验证重点 |
| --- | --- |
| 原五题 | 题面及语料保持原样；无关查询的拒绝必须有业务原因，不能由服务失败替代 |
| 非空但无关的 dense 命中 | 即使有正分数、真实页码和有效原文，仍按相关性契约判断；不靠“召回数量大于零”放行 |
| 同义改写、间接提问及正常宽泛阅卷问题 | 保护有效问题；不能因缺少字面重合或未点名文档而全部拒绝 |
| 部分相关、同名词不同事项、歧义或证据不足 | 明确支持范围与不足原因；不能用一段相关原文为全部结论背书 |
| 多页证据、矛盾及证据缺口 | 正常召回、专家链路与引用不退化；无关邻页或记忆不能把无支持的问题变成成功 |
| 无来源、纯法条等已有边界 | 按既有能力契约处理，保留来源类型及规模限制，不扩大本批承诺 |
| 模型主动拒答、规则 fallback、服务失败、非法输出、缺失 usage | 有依据的拒答不能被规则汇总重新包装成成功回答；系统失败与业务拒绝分别记录，无效/未知测量不能被标为正确负例 |
| 新进程恢复及身份变化 | 重用已确认决策和响应；版本/来源/权限变化时按契约拒绝或明确处理，不盲重算或续用失效批准 |

开发调参与新增保留样本分开。新增保留题在方案及参数冻结后执行；原失败题已经参与开发，不能再充当独立泛化证明。开发材料与≥16 个独立业务题的 E17 终评材料也须分开封存。

现有 `tests/test_model_comparison.py` 中记录无关 dense 查询错误成功的用例，应保留输入与失败机制并转为正确拒绝的回归断言，不能简单删除；已有离线 hashed-local 拒绝测试不能替代远程 embedding 路径的验证。

### 4.2 对照基线及判定

- 固定修复前源码 `ab779cb` 及其模型、提示词、配置和资料身份。公共 helper 同时影响候选与原生时，明确记录影响，不能让对照基线随修复静默变化。
- 共享检索/记忆对照用于定位编排和决策差异；独立检索对照记录各自命中与差异原因。检索不同或候选正确拒绝、旧基线错误接受时保留差异，不以强制答案相同作为正确性标准。
- 分别记录候选正确性、原生基线缺陷、来源身份、工程一致性和测量有效性。两边同样错误不能记为通过；对新拒绝契约新增报告版本和断言，保留旧报告的原始判据及结论。
- 零容忍项按 E03 执行：权限泄漏、未批准/重复副作用、虚假完成、引用身份错误在适用集零失败；关键业务题不得新增严重错误。
- 同模型、材料和并发条件下，沿用 p95 ≤ 基线 1.20 倍、实际 token ≤ 基线 1.10 倍的候选要求。五题不足以支撑稳定的总体分位数结论，报告原始分布和样本限制；卸载/加载、治理及整次墙钟开销分别记录。用量未知不填零、不声称满足比例。
