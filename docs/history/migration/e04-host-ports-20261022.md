## 2. 读端口（[app/host_ports.py](../../../app/host_ports.py)）

**分层**：`LocalHostReadPort`（绑定单个 `RunScope`）→ 内部守卫 → 业务读（`connect()` 尊重当前 `db_scope`）。

| 守卫 | 行为 |
| --- | --- |
| `_bind(scope)` | 调用作用域必须与实例绑定作用域逐字段相同（防混淆代理）；每次调用重新校验 `view` 权限与案件归属（撤权立即生效） |
| 版本检查 | `expected_source_identity` 固定时，每次读取前比对**源库**内容摘要；变化 → `SnapshotChangedError`（失败关闭） |
| `identity_source_path` | 身份检查始终指向受权**源库**，读取跟随活动作用域（M2 会话读私有快照副本，而快照会刻意清除来源文件路径，二者必须分离） |
| 边界 | 查询 1..500 字符；目录上限 1..100；检索 1..20；记忆 1..50；法条 1..20；单页 ≤20000 字符；超限 → `ContractValidationError`（**不截断**） |
| 远程能力 | 部署声明 `allow_remote_embeddings=False` 时，请求远程嵌入 → `UnsupportedCapabilityError` |
| 法条 | 语料未配置 → `UnsupportedCapabilityError`；已配置则返回带 `corpus_version` 的类型化命中；`statutory_lookup()` 额外保留领域形态（status/mode/summary/hits/warning）供法条专家使用 |
| 访问记录 | `access_recorder(kind, {case_id, count/ids…})`，**不含案件正文**；M2 记入隔离实验日志，M4 接业务审计 |

**类型映射**：`search_hit_from_legacy`/`search_hit_context` 与 `memory_record_from_legacy`/`memory_record_context` 保证域内上下文可精确往返（测试断言与 `agent_tools._search` 原始输出**逐字段相等**），使既有专家函数无需改动即可复用。

## 3. 控制面（[app/forge_runtime.py](../../../app/forge_runtime.py)）

**能力声明（诚实，不推断）**：运行时 `{forgeharness-readonly}`；`start_modes={sync}`；`resumable_runtimes=∅`；`background_start`/`budget_enforcement`/`event_projection`/`idempotent_start`/`persistent_request_mapping` 全为 **False**（本轮无持久请求映射，重复 `request_id` 视为新实验；幂等与持久映射由 M4/E13 提供）。

**`start()` 语义**：能力/参数校验 → 构造已授权会话（身份、权限、案件、快照边界在此校验；解释器在授权**之后**解析，避免向未授权调用方泄露配置状态）→ 独立解释器运行 → 映射治理事实（`source_identity`、`framework_version`、`wheel_sha256`、`tool_calls`、`framework_trace_valid`/事件数、工具证据数、消息数、`port_access_log`、对照结果、`source_business_writes=0`、`business_qualified=false`、`model_quality_assessed=false`）。

**结果诚实性**：框架 `status=succeeded` → `completed`；框架报告失败 → `failed` + `RunError(framework_readonly_failed)` + 诊断（保留结果供报告）；协议/超时/IO 异常 → 状态 `unknown` + `needs_reconciliation=True`（**不冒充成功或失败**；本轮只读、源库零写入）。

**显式拒绝**：非 `forgeharness-readonly` 运行时、后台模式、预算、模型覆盖、`use_llm`、远程嵌入、记忆持久化、未配置解释器 → 契约错误或 `UnsupportedCapabilityError`；`inspect`→`UnsupportedCapabilityError`、`resume`→`ResumeNotSupportedError`、`status`→`UnsupportedCapabilityError`。

## 4. 契约变更登记

| 变更 | 类型 | 版本影响 | 理由 |
| --- | --- | --- | --- |
| 新增 `UnsupportedCapabilityError(RuntimeContractError)` | **附加式** | 不升版（协议 v2 不变） | 计划书要求"不支持能力显式拒绝"；此前只能借用 `UnsupportedExecutionModeError`（语义不符）或返回空结果（禁止）。既有调用方与序列化不受影响 |

未改动：`RunRequest`/`RunResult`/`RunEvent`/`RunTrace`/`RunHandle`/`JobStatus`/`RuntimeCapabilities` 字段、七个读方法签名、写端口占位、`RUNTIME_PROTOCOL_VERSION`。

## 6. 偏差与限制（如实记录）

1. **未接 HTTP/UI**：端口与控制面均为 Python 接口，正式入口接线属 E14。
2. **无业务审计**：M2/M4 之前访问只记入隔离实验日志（`port_access_log`）；业务审计在 E12/E14。
3. **无持久幂等**：`idempotent_start=false`；重复请求不做去重（M4/E13）。
4. **法条仅词法**：`search_statutes` 走既有 `LegalCorpus`（TF-IDF），无向量；语料未配置时明确拒绝。
5. **远程后端未验证**：`allow_remote_embeddings=False` 是本轮部署事实；远程路径需 E05 与 E03 的模型/预算授权后才能验证。
6. **运行时偏差**：本机 node v24.21.0 vs CI node 22（M2 记录已在案，不影响本次结果）。
7. **框架解释器**：沿用 `.venv-framework-m2`（0.6.0，wheel `69ce604c…`）；CI 由 `scripts/setup_framework.py` 独立准备。
